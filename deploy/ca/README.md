# 사내 CA 인증서 자리

사내 LLM이나 사내 IdP(OIDC)가 **사내 인증 기관(CA)이 서명한 https 인증서**를 쓰면, 그 기관의 인증서(PEM)를 이 디렉토리에
**`ca.pem`**이라는 이름으로 두고 앱을 다시 만든다(`docker compose -f compose.yml --env-file .env up -d --force-recreate api`). 앱이 그 기관을
믿는다 — TLS 검증은 끄지 않는다. **`--force-recreate`를 빼면 아무 일도 없다** — 파일을 둔 것은 설정이 바뀐 것이 아니라 `up -d`가 알아채지
못한다.

- 파일이 없으면 아무 일도 없다. compose를 고치지 않는다
- 기관이 여럿이면 한 파일에 이어 붙인다(PEM 여러 개)
- 인증서는 저장소에 넣지 않는다(`.gitignore`) — 현장의 것이다. 반입 묶음에는 이 안내만 들어가 디렉토리가 풀린 사람의 것으로 생긴다
  (없으면 첫 기동에서 도커가 root 소유로 만들어 인증서를 넣지 못한다)

절차 전체는 반입 가이드 10절 "사내 LLM 연결하기"다 — 반입 묶음에서는 `반입절차.md`, 저장소에서는 `docs/운영가이드_반입.md`.
설계는 저장소의 `docs/P11_설계서_Ops.md` D.7.
