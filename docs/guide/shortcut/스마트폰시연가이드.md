# 스마트폰 시연 가이드 — 점심 자리에서 폰 하나로 보여 주기

> 기능백로그 **F-015**(사용자 요청 2026-10-15, 원문 [`docs/prompts/android-demo.md`](../../prompts/android-demo.md)). 폐쇄망 반입과 무관한 시연이다.
> 이 앱은 **시연판**이다. 서버 없이 폰 안에서만 돌고, 인터넷을 쓰지 않으며, 내용은 모두 지어낸 시연 데이터다(`CLAUDE.md` 12.3절).
> 실제 시스템은 사내 서버 한 대에 설치한다 — [설치및실행가이드](../설치및실행가이드.md).

| 알고 싶은 것 | 절 |
|---|---|
| 폰에 까는 법 | 1 |
| 시연 전에 확인할 것 | 2 |
| 무엇을 어떤 순서로 보여 주나 | 3 |
| 무엇을 말하나 (4분 30초판 · 1분판) | 4 |

## 1. 설치

1. 폰 브라우저(크롬·삼성 인터넷)에서 아래 주소를 연다.
   `https://github.com/hipiboy7/workfluence/releases/tag/android-demo`
2. **Assets**의 `workfluence-demo.apk`를 누른다. 받은 파일을 연다.
3. 막히면:
   - "출처를 알 수 없는 앱" — 그 브라우저에 **이 출처 허용**을 켠다.
   - 삼성 **자동 차단** — 설정 → 보안 및 개인정보 보호 → 자동 차단을 끈다(설치 뒤 다시 켜도 된다).
   - Play 프로텍트 경고 — **세부정보 → 무시하고 설치**.
   - 회사 관리 폰이라 위를 끌 수 없으면 개인 폰을 쓴다.
4. 앱 이름은 **workfluence 시연판**, 아이콘은 파란 바탕의 **wf**다.

**새 판을 받으면** 지우지 않고 그대로 덮어 설치한다(같은 서명 키다). 릴리스 제목의 `#번호`가 판 번호다. 덮어 설치해도 폰 안의 시연 데이터는 남는다 — 처음 상태로 돌리려면 **시연 데이터 처음으로**를 누른다.

## 2. 앱 기능 체크리스트

시연 전날 한 번, 당일 아침 한 번 위에서부터 짚는다. 시연판에서 **하지 않는 것**(정상): 실시간 동시 편집 · 사내 LLM 질문 · 메일 · 사내 계정(IdP) 로그인 · 첨부 올리기·받기 · HTML 내보내기 · 사용자 관리의 조치.

가. 설치·실행
- [ ] 1 앱 이름이 **workfluence 시연판**이고 아이콘이 wf다
- [ ] 2 **비행기 모드(와이파이도 끔)**에서 열면 3초 안에 로그인 화면이 뜬다
- [ ] 3 세로로 고정되고, 위 막대가 상태 표시줄에 가리지 않는다
- [ ] 4 뒤로 가기: 열린 서랍·알림 판·대화를 먼저 닫고, 그다음 앞 화면으로, 첫 화면(스페이스·로그인)에서는 앱이 닫힌다
- [ ] 5 껐다 켜도 고친 내용이 남고, **시연 데이터 처음으로**(로그인 화면, 스페이스 목록 맨 아래)를 누르면 처음 상태가 된다

나. 로그인
- [ ] 6 로그인 화면에 시연 계정 단추 둘이 있다 — **김운영 · 팀원 (시연)**, **이관리 · 관리자 (감사로그)**. 누르면 바로 들어간다(비밀번호 `demo1234`). 로그아웃 뒤 다시 들어간다

다. 스페이스·트리
- [ ] 7 김운영의 첫 화면에 **김운영의 메모(개인)** · **IT운영팀** · **IT인프라팀** · **보안**이 있다
- [ ] 8 IT운영팀을 누르면 **문서** 트리가 3단계(운영 개요 → 장애 대응 절차 → 장애 등급 기준)로 들여 써 보인다. ☰를 누르면 같은 트리가 서랍으로 열리고, 페이지를 누르면 서랍이 닫힌다

라. 보기·편집
- [ ] 9 제목·목록·표·인용·코드가 폰 폭에 맞는다(넓은 표와 코드는 옆으로 민다)
- [ ] 10 편집에서 **삼성 키보드로 한글 한 줄**을 쳐도 글자가 겹치거나 사라지지 않는다
- [ ] 11 **B**(굵게)·목록 → **저장** → 보기 화면에 반영되고 버전이 하나 오른다
- [ ] 12 IT운영팀 첫 화면의 **새 페이지**에서 템플릿 **회의록**으로 만들면 트리에 생긴다

마. 이력
- [ ] 13 장애 대응 절차의 이력에 버전이 5개 있다(김운영·박서버·최디비 세 사람이 고쳤다)
- [ ] 14 두 버전의 **비교**를 고르고 **비교하기**를 누르면 바뀐 것만 보인다 — 더한 글은 초록 `+`, 지운 글은 빨강 `−`, 고친 글은 노랑 `~`
- [ ] 15 **이 버전으로 복원**을 누르면 새 버전으로 쌓이고 이력은 지워지지 않는다

바. 검색·라벨
- [ ] 16 검색 "장애"가 10건 넘게 나오고 본문에서도 찾는다(제목에 없는 회의록·월간 서버 점검). 두 글자 "배포"도 찾는다
- [ ] 17 문서 아래 라벨(예: 장애)을 누르면 같은 라벨의 문서 목록이 나온다

사. 댓글·알림
- [ ] 18 장애 대응 절차 아래 댓글이 둘 있고(박서버·최디비), 새 댓글을 쓰면 바로 보인다
- [ ] 19 위 막대 **알림**에 숫자 2 → 누르면 "최디비님이 불렀다 · 장애 대응 절차" → 그 문서로 간다

아. 권한·감사
- [ ] 20 **보안** 공간의 문서에는 편집·하위 페이지·옮기기·삭제 단추와 댓글 칸이 없다(김운영은 viewer). Crew 표에 "viewer (읽기만)"이 보인다
- [ ] 21 로그아웃 → **이관리**로 들어가 **관리**를 누르면 감사로그가 열리고, 맨 위 가까이에 방금 한 **페이지 저장 page.update · 김운영 · versionNo**가 있다

자. 시연 조건
- [ ] 22 비행기 모드에서 1~21이 모두 된다
- [ ] 23 **시연 데이터 처음으로** → 3절 순서를 두 번 연달아 해도 깨지지 않는다

## 3. 시연 순서 (4분 30초)

**전날**: 최신 APK 설치 → 2절 체크리스트 → 4절 스크립트로 한 번 리허설(시간 잰다).
**당일 아침**: 충전 80% 이상 → **시연 데이터 처음으로** → 김운영으로 들어가 첫 화면에 둔다.
**식당 들어가기 전**: 비행기 모드(와이파이도 끔) · 방해 금지 · 밝기 올림 · 화면 꺼짐 5분 이상.

| # | 장면 | 시간 | 화면에서 할 것 |
|---|---|---|---|
| 0 ★ | 꺼내기 | 15초 | 상태 표시줄의 비행기 아이콘을 보이고 앱을 연다 |
| 1 | 스페이스·트리 | 30초 | 첫 화면의 공간 넷 → **IT운영팀** → 문서 트리 → **장애 대응 절차** |
| 2 | 편집 | 60초 | **편집** → 본문 맨 끝(마지막 문단 뒤) 누르고 줄 바꿈 → **B** → 한 줄 → **저장** |
| 3 ★ | 이력·비교 | 45초 | 버전 옆 **이력** → 맨 위 둘(v6·v5)의 **비교** → **비교하기** → 초록 `+` 한 줄 |
| 4 | 검색 | 20초 | 위 **검색** → "장애" → 찾기 |
| 5 | 알림·댓글 | 30초 | 위 **알림** → "최디비님이 불렀다 · 장애 대응 절차" → 문서 아래 댓글 |
| 6 | 권한 | 20초 | 위 **스페이스** → **보안** → 보안 정책 개요 → 편집 단추가 없다 · Crew의 "viewer (읽기만)" |
| 7 ★ | 감사로그 | 30초 | **로그아웃** → **이관리 · 관리자** → 위 **관리** → 맨 위의 로그인·로그아웃 아래 **페이지 저장 · 김운영** |
| 8 | 마무리 | 30초 | 폰을 내려놓고 말로 |

밥이 나와서 짧게 해야 하면 **1분판: 0 → 2 → 3 → 7**.
시간이 모자라면 6 → 5 → 4 순으로 뺀다. 0·2·3·7은 끝까지 지킨다.

막히면:
- 데이터가 꼬였다 → 스페이스 목록 맨 아래(또는 로그인 화면) **시연 데이터 처음으로**.
- 서랍이 열려 화면을 가린다 → 어두운 곳을 누르거나 뒤로 가기.
- 비교하기가 회색이다 → 버전 **두 개**의 "비교"를 골라야 한다.

| 진짜로 저장되나, 가짜 아니냐 | 시연판은 서버 대신 폰 안에 저장합니다. 문서 검사·버전 비교·권한 판정은 실제 시스템과 **같은 코드**를 씁니다. 껐다 켜도 남아 있습니다 |

## 6. 시연판이 만들어지는 길

- 화면은 실제 시스템의 화면(`apps/web`) 그대로다. **시연 빌드**(`vite build --mode demo`)일 때만 화면이 서버 대신 폰 안의 시연 저장소(`apps/web/src/demo/server.ts`)에 묻는다. 시연 저장소는 실제 시스템의 공유 코드(`packages/shared` — 문서 검사·버전 비교·권한 판정)를 쓰고, 고친 것은 폰의 저장소(localStorage)에 남는다. 실시간 편집은 끈다(저장 단추로 버전을 남긴다).
- 폰 화면 맞춤(`apps/web/src/demo/demo.css`)과 시연 데이터(`apps/web/src/demo/seed.ts`)도 시연 빌드에만 들어간다. **제품 빌드(app 이미지·반입 묶음)는 바뀌지 않는다** — 워크플로가 제품 산출물에 시연 코드가 없는지 본다.
- 안드로이드 껍데기는 Capacitor(MIT, `apps/mobile`)다. pnpm 작업공간과 도커 빌드 밖이라 제품 lockfile과 이미지에 들지 않는다.
- APK는 GitHub의 Linux 러너가 만든다(`.github/workflows/android-demo.yml`) — 이 저장소의 `exp/android-demo`에 화면·껍데기가 바뀐 커밋을 올리면 돈다. 서명 키는 저장소에 두지 않고 GitHub 비밀값(`ANDROID_DEMO_KEYSTORE_B64`·`ANDROID_DEMO_KEYSTORE_PASSWORD`)에 있다. 결과는 미리보기 릴리스 `android-demo`에 올라간다(1절의 주소).
- 시연 저장소의 동작은 시험(`apps/web/src/demo/server.spec.ts`)이 본다 — 시연 데이터가 서버의 문서 검사를 통과하는지, 시연 장면이 기대는 권한·버전·비교·검색·알림·감사가 맞는지.
