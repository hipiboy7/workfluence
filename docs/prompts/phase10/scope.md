## 2026-09-25 · 착수 쟁점의 답

Claude가 두 번에 나눠 여덟 가지를 물었다 (1.1절 1단계). 사용자가 고른 것과 직접 쓴 답을 그대로 둔다.

**질문 1.** LLM과 나눈 대화를 서버에 저장할까요? 질문에 업무 내용이 들어가므로 문서 본문과 같은 수준으로 다뤄야 합니다.

- 저장 안 함 (Recommended)
- **기간 한정 저장** ← 선택 — 사용자별로 저장하고 보존 기간과 개수 상한을 두어 배치로 지운다
- 무기한 저장

**질문 2.** 관리자가 등록하는 LLM API 키를 어디에 둘까요?

- **DB에 암호화 (Recommended)** ← 선택 — 관리 화면에서 등록·삭제. 키는 .env의 마스터 키(WF_*)로 암호화해 DB에 넣고 화면에는 다시 보여주지 않는다
- DB에 평문
- 키 없음 전제

**질문 3.** LLM 질문 메뉴는 누가 쓸 수 있나요?

- **활성 사용자 전원 (Recommended)** ← 선택 — 로그인한 모든 member 이상. 관리자는 등록·삭제만 한다
- 관리자가 켠 사람만
- admin 이상만

**질문 4.** 첫 판에서 위키 페이지 내용을 질문에 함께 넣을 수 있게 할까요?

선택지(넣지 않음 · 지금 보는 페이지 하나 · 검색 결과 여러 개) 대신 직접 답했다.

> 넣지 않는다. 그러나 위키에서 '복사' 기능을 두고, 붙여넣기 할 수 있도록 해두어야 한다. 또한 시스템 프롬프트 기능이 있어야 하며, 사용자별로 해당 내용은 수정 또는 삭제 전까지 저장 및 유지되어야 한다.

**질문 5.** 대화 보존 기간과 상한을 어떻게 둘까요? (관리자가 관리 화면에서 바꿀 수 있는 정책값으로 둡니다 — 5절)

선택지(30일·100개 · 90일·300개 · 7일·30개) 대신 직접 답했다.

> 7일, 사용자당 100개, 그러나 '즐겨찾기' 또는 '고정' 설정을 하면 사용자가 해당 설정을 해제 할때까지 영구히 보관 가능. '즐겨찾기', '고정'은 100개에 포함. 즉, 즐겨찾기나 고정은 최대 20개까지만 가능하고, 20개를 채우면 보관할 내용은 80개로 되는 것.

**질문 6.** 사용자별 시스템 프롬프트는 하나만 둘까요, 여러 개를 저장해 골라 쓰게 할까요?

- **여러 개 저장·선택 (Recommended)** ← 선택 — 이름을 붙여 여러 개 저장하고 대화를 시작할 때 고른다. 수정·삭제 전까지 유지
- 사용자당 하나

**질문 7.** 위키 페이지의 '복사' 기능은 무엇을 클립보드에 넣을까요?

- 제목 + 본문 텍스트 (Recommended)
- 마크다운
- **둘 다 (버튼 둘)** ← 선택 — 텍스트와 마크다운을 따로 복사

**질문 8.** LLM 응답을 글자가 나오는 대로 흘려보낼까요(스트리밍)?

- **흘려보낸다 (Recommended)** ← 선택 — vLLM의 stream 응답을 서버가 받아 화면으로 중계. nginx에 버퍼링 끄기 설정이 한 줄 늘고 반입 구성이 바뀐다
- 다 받은 뒤 한 번에
