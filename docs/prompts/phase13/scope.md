# Phase 13 요청 원문

`CLAUDE.md` 11절. **사용자의 말을 그대로 둔다.** 요약하면 의도가 사라진다.

## 2026-09-27 · Phase 12 병합 뒤 "이어서 진행할 항목"에 대한 답

Phase 12(PR #11) 병합 뒤 이어서 할 것을 묻자, 지금 개발 서버에서 할 수 있는 셋(① 보류 16 판정 측정 ② 보류 19 합성 측정 ③ Phase 12에서
남은 확인)과 사용자 답이 필요한 것(확인 필요 A·B·C)을 제안하고 ①을 추천했다. 사용자의 답:

> 아래 1,2,3번 확인해서 알려주거나 실행하고, 만약 1,2,3을 병렬로 실행할 수 있으면 별도 agent로 띄워서 진행해줘.
> 1. 우선 지금까지 개발 된 상태에서 배포 및 운영을 할 수 있는지 봐줘.
> 그리고 그게 가능하다면 설치 및 실행 방법 알려줘. 혹시 이미 설치 및 실행 가이드, 운영 가이드, 사용자 가이드가 이미 작성되어있다면 그걸 알려줘도 돼.
> 2. 만약 설치 및 실행 가이드, 운영 가이드, 사용자 가이드가 없다면 별도 agent(OPUS 5.5, Effort MAX로) 바로 만들어줘.
> 3. 1번 보류 16 측정 진행해줘.(OPUS 5.5, Effort MAX로)

"3.의 1번"은 제안 목록의 ①(보류 16 판정 측정)이다.

## 2026-09-27 · 착수 쟁점의 답

세 에이전트의 결과(배포 점검·사용자 가이드·보류 16 측정)를 보고하며 물었다. 사용자가 고른 답을 그대로 적는다.

| 물은 것 | 사용자의 선택 |
|---|---|
| 설치 가이드·빌드 가이드·반입 묶음의 결함(root 계정 단계, alpine 백업, 묶음에 운영 문서 넣기, 빌드 가이드 다시 쓰기)을 이번 Phase 13에서 고칠까요? | 고치고 리허설까지 |
| 폐쇄망에서 매월 하는 정리 작업(휴지통·감사로그 정리, 검색 재색인)을 어떻게 할까요? | 컨테이너에서 돌게 |
| 사용자 가이드를 쓰다가 코드에서 나온 제품 결함을 어디까지 이번에 고칠까요? | 계정 정지까지 |
| 앱이 DB에 최고 권한 계정으로 접속하는 것(보류 12)을 언제 고칠까요? | 반입 전에 |
| 보류 16(로그인이 몰리면 다른 사람의 요청까지 느려짐)을 어떻게 할까요? | 이번에 고치기 |
| 측정하다 찾은 보안 결함 둘(동시에 틀린 비밀번호를 보내면 잠금이 안 걸림, 잠긴 계정이 응답 시간으로 드러남)을 어떻게 할까요? | 이번에 고치기 |

"계정 정지까지"는 선택지의 설명대로 "운영에 걸리는 것(사용자 목록 100명 상한과 찾기, 제목 자동 저장, 작은 화면 오류)에 더해
계정 정지(퇴사자 처리)도 이번에 만든다"이다. 페이지 옮기기·스페이스 상태 변경은 기능백로그로 간다.
