# Phase 6 착수 — 사용자 원문 (2026-09-22)

`CLAUDE.md` 11절: **사용자가 한 말의 원문만** 둔다. 요약하면 의도가 사라진다.

## 진행 지시

> phase 6까지 진행해

앞선 두 지시에 있던 "물어보지 말고"가 **이번에는 없었다.** 그래서 1.1절 1단계대로
**사용자가 정해야 하는 것만** 골라 물었다 — Phase 6에 묶여 있던 다섯 항목 중 셋이
사용자만 답할 수 있는 것(발송 경로의 존재, 이관 데이터의 존재, 반입 용량의 값어치)에
막혀 있었기 때문이다.

## 착수 쟁점에 대한 답

물은 것과 받은 답 넷이다.

| 물음 | 답 (원문) |
|---|---|
| Phase 6에 무엇을 넣을까요? | **"위 전부 + 템플릿"** |
| PDF 내보내기는 어떻게 할까요? | **"하지 않는다 — HTML + 인쇄 CSS로"** |
| 외부 알림을 만들 수 있는 상태인가요? | **"메일 전송 API 기능이 있다."** |
| Confluence 데이터 가져오기는요? | **"이관하지 않는다 — 닫는다"** |

## 이 답들이 산출물에 미친 것

- **"위 전부 + 템플릿"** → 실시간 편집·비교·HTML 내보내기·템플릿·메일 다섯을 한
  Phase에 넣었다. 지금까지 중 가장 큰 Phase다.
- **PDF를 안 한다** → 보류 7을 "하지 않는다"로 닫았다. app 이미지가 390MB로 예산
  400MB에 10MB만 남은 것이 판단의 근거였고, 그 수치를 설계서 쟁점 2에 적었다.
- **"메일 전송 API 기능이 있다"** → `scope-definition` 4.2절이 기다리던 조건이
  충족됐다("폐쇄망에서 발송 경로가 확정되지 않았다"). 다만 **그 API의 요청 형식은
  말해 주지 않았고 나도 묻지 않았다** — 주입 토큰 뒤에 두고 가정을 설계서 A.1절에
  적는 쪽을 골랐다. 틀리면 어댑터 한 파일을 고친다. 실연동 확인은 보류 18이다.
- **"이관하지 않는다"** → `scope-definition` 4.2절에서 닫았다. 새로 시작한다.

> **형식을 되묻지 않은 것은 판단이었다.** 사용자가 자리를 비운 상태에서 한 번 더
> 묻고 멈추는 것보다, 바뀔 수 있는 것을 인터페이스 뒤에 두고 진행하는 편이 낫다고
> 봤다. 이 프로젝트가 IdP에 대해 이미 그렇게 하고 있다 (9.1절).
