# P10 설계서 — Llm (사내 LLM 질문)

Phase 10은 **기능백로그 F-002**를 만든다 — 사내에 따로 선 LLM 서버(vLLM, Qwen3)에 위키 안에서 묻는 메뉴다.
시스템 관리자가 관리 화면에서 LLM을 등록·삭제하고, 사람마다 자기 지시문(시스템 프롬프트)을 여럿 저장해 골라 쓰고,
대화는 정해진 기간·개수만큼 남는다. 위키 페이지는 텍스트·마크다운으로 복사해 질문에 붙인다.

요청 원문과 착수 쟁점의 답은 `docs/prompts/phase10/scope.md`다. 요구사항 번호는 **FR-1100**, 비기능은 **NFR-100**부터다.
이 Phase는 **보류 28**(web 컴포넌트 시험 틀)의 트리거이기도 하다 — J절.

선행: [`docs/P9_검증기록_Gate.md`](P9_검증기록_Gate.md) · 구조: [`docs/설계서_Architecture.md`](설계서_Architecture.md)

> **경로에 백틱이 없는 것은 아직 만들지 않은 것이다** (4.1절). 만들면 붙인다.

## A. 착수 쟁점 (사용자 결정 2026-09-25)

| # | 쟁점 | 결정 | 이 설계에서의 뜻 |
|---|---|---|---|
| 1 | 대화를 서버에 저장하나 | **기간 한정 저장** | 사용자별로 저장하고 보존 기간과 개수 상한을 두어 지운다(D.5). 질문에 업무 내용이 들어가므로 문서 본문과 같은 수준으로 다룬다 — 로그에 남기지 않고(FR-1117), 관리자도 남의 대화를 볼 경로가 없다(FR-1139) |
| 2 | 관리자가 등록하는 API 키를 어디에 | **DB에 암호화** | `.env`의 마스터 키(`WF_LLM_MASTER_KEY`)로 암호화해 넣고 **화면에는 다시 보여 주지 않는다** — "키 있음/없음"만(D.4) |
| 3 | 누가 쓰나 | **활성 사용자 전원** | 로그인한 모든 사람. 관리자는 등록·삭제만 한다 |
| 4 | 위키 내용을 질문에 넣나 | 사용자 답: "넣지 않는다. 그러나 위키에서 '복사' 기능을 두고, 붙여넣기 할 수 있도록 해두어야 한다. 또한 시스템 프롬프트 기능이 있어야 하며, 사용자별로 해당 내용은 수정 또는 삭제 전까지 저장 및 유지되어야 한다." | 서버가 페이지를 LLM에 보내는 길은 없다. **무엇이 LLM 서버로 가는지 사람이 보고 붙인다.** 페이지 보기에 복사 버튼(FR-1140), 지시문은 고치거나 지울 때까지 남는다(FR-1126) |
| 5 | 보존 기간과 상한 | 사용자 답: "7일, 사용자당 100개, 그러나 '즐겨찾기' 또는 '고정' 설정을 하면 사용자가 해당 설정을 해제 할때까지 영구히 보관 가능. '즐겨찾기', '고정'은 100개에 포함. 즉, 즐겨찾기나 고정은 최대 20개까지만 가능하고, 20개를 채우면 보관할 내용은 80개로 되는 것." | 고정하지 않은 대화는 마지막 사용 뒤 7일, 사람마다 100개(고정 포함), 고정은 20개까지. 세 값은 운영 설정에서 바꾼다(5절 세 번째 분류, I절). "즐겨찾기"와 "고정"은 **한 기능**으로 읽었다 — 화면 이름은 "고정" |
| 6 | 지시문은 하나인가 여럿인가 | **여러 개 저장·선택** | 이름을 붙여 여럿 저장하고 **새 대화를 시작할 때** 고른다 |
| 7 | 복사는 무엇을 | **둘 다 (버튼 둘)** | "텍스트 복사"(제목 + 본문 평문) · "마크다운 복사" |
| 8 | 답을 흘려보내나 | **흘려보낸다** | vLLM의 stream 응답을 서버가 받아 화면으로 중계한다(D.1). 버퍼링을 끄는 것은 앱이 응답 머리말로 한다(D.1 — nginx 설정을 늘리지 않았다) |

## A.1 묻지 않고 정한 것 — 근거와 되돌릴 조건

사용자 지시(2026-09-25): "진행 중에 필요한 결정사항이 생기면 보류로 넘기고 나머지를 이어서 진행해." 그래서 아래는 Claude가 정했고,
**다르게 보면 그 항목만 뒤집는다.** 사용자에게 확인할 것은 `CLAUDE.md` 1.2절의 확인 필요 F와 보류 29로 올렸다.

| # | 정한 것 | 근거 | 되돌릴 조건 · 자리 |
|---|---|---|---|
| 1 | LLM 등록·삭제는 **root만**(`system.manage`) | 요청 원문이 "'시스템 관리자'가 '시스템 관리자 화면'에서"다. 이 시스템에서 "시스템 관리자"는 root 계정의 이름이고(`apps/api/src/db/seed.ts`), `system.manage`는 "시스템 운영(설정·기반)"을 위해 root에게만 둔 행위다(`scope-definition` 7.3절). 사내 다른 서버로 나가는 길과 그 키를 정하는 일이라 업무 관리(admin)보다 시스템 운영에 가깝다 | admin도 해야 하면 `packages/shared/src/permissions.ts`에서 행위 하나를 admin에게 준다 (확인 필요 F) |
| 2 | 요청 형식은 **OpenAI 호환**(`/chat/completions`, `/models`) | vLLM이 내는 API가 이것이다. 주소는 `/v1`까지 적는다(`http://llm.example.internal:8000/v1`) | 사내 LLM 앞에 다른 형식의 게이트웨이가 있으면 **어댑터 한 파일**만 바꾼다(2절 DIP — `LLM_CLIENT`). 실연동 확인은 보류 29 |
| 3 | Qwen3의 **생각 과정**은 흘러나오는 동안 접어서 보여 주고, **저장하지 않고, 다음 질문의 이력에 넣지 않는다** | Qwen3 사용 권고가 "이력에는 최종 답만 넣는다"이다. 생각 과정은 답보다 몇 배 길어 저장 공간과 다음 질문의 문맥을 먼저 채운다 | 생각 과정도 남기자는 요구가 오면 `llm_messages`에 열 하나 |
| 4 | 답은 **평문으로** 그린다 (줄바꿈 유지). 마크다운을 HTML로 그리지 않는다 | 마크다운을 HTML로 그리면 렌더러와 정화기(sanitizer)가 들어오고, 그 정화 규칙의 구멍이 그대로 XSS다(`scope-definition` 7.4절 "HTML을 받지 않는다"와 같은 판단). 답마다 "답 복사"가 있어 위키에 붙이면 거기서 읽힌다 | 서식 표시 요구가 오면 허용 목록 방식의 렌더러를 따로 판단한다 |
| 5 | 보존 기간은 **마지막 질문 시각**부터 센다. 고정을 풀면 **그때부터** 다시 센다 | "7일"을 만든 시각부터 세면 어제도 쓰던 대화가 사라진다. 풀자마자 지워지면 "풀 때까지 보관"의 뜻이 어긋난다 — 풀면 보통 대화가 되어 그때부터 7일이다 | D.5의 `retain_from` 한 열 |
| 6 | 상한을 넘으면 **거부하지 않고** 고정하지 않은 것 중 **가장 오래된 것**을 지운다 | 사용자 답이 "보관할 내용은 80개로 되는 것" — 상한은 보관의 크기이지 질문의 문턱이 아니다. 지운 수는 그 자리에서 화면에 말한다(FR-1132) | — |
| 7 | 만료된 대화는 **앱이 한 시간마다 스스로** 지운다. 명령을 따로 두지 않는다 | `pnpm trash:purge`를 사람이 부르게 한 것(P4 쟁점 6)과 판단이 다르다. 휴지통은 되살릴 수 있는 것을 영구히 지우는 일이라 사람의 판단이 끼일 자리가 있지만, 이것은 **사용자가 정한 보존 규칙**이고 되살리기가 없다. 7일은 사람이 명령을 돌리는 주기보다 짧아, 명령에 맡기면 규칙이 지켜지지 않는다. 단일 앱 서버라(0.1절) 한 프로세스의 타이머로 충분하다 | 여러 대가 되면 잠금을 건다 (보류 6이 닫혀 있다) |
| 8 | 감사로그: **등록·삭제, 질문마다(내용 없이), 만료 삭제** | 6절 "관리자 작업". 질문은 업무 내용이 사내 다른 서버로 나가는 길이라 누가·언제·어느 LLM에·얼마만큼을 남긴다 — 대화가 7일 뒤 지워져도 흔적은 남는다. 지시문·고정·대화 삭제는 자기 데이터의 일이라 남기지 않는다(FR-507과 같은 판단: 양이 불어나고 추적 가치가 낮다) | — |
| 9 | **복사는 감사하지 않는다** | 이미 볼 수 있는 글을 골라 Ctrl+C 하는 것과 같다 — 그것은 기록할 수 없고, 버튼만 기록하면 기록이 흉내가 된다. HTML 내보내기(`page.export`)는 앱 밖으로 나가는 **파일**을 만들어 다르다 | — |
| 10 | "시스템 프롬프트나 프리프롬프트"를 **지시문 하나**로 받는다 | 둘 다 "질문 앞에 늘 붙는 지시"의 뜻으로 읽었다. 둘을 나누면 같은 일을 두 곳에서 한다 | 따로 필요하다는 말이 오면 지시문에 "질문 앞에 붙일 글" 열을 더한다 |
| 11 | 한 사람이 **동시에 하나만** 묻는다 | GPU 서버는 사내 공용이다. 한 사람이 탭 여럿으로 동시에 흘려받으면 남의 답이 느려진다 | — |
| 12 | 지시문은 **새 대화를 시작할 때 복사된다** | 쟁점 6 "대화를 시작할 때 고른다". 나중에 지시문을 고쳐도 진행 중인 대화가 바뀌면 같은 대화 안에서 앞뒤 답의 전제가 달라진다 | — |
| 13 | 보류 28: **들인다** — `happy-dom` + Testing Library | J절 | — |

## C. 요구사항

### C.1 LLM 연결 관리 (FR-1100 ~ FR-1108)

| # | 요구 | 근거 |
|---|---|---|
| FR-1100 | root가 관리 화면에서 LLM을 **등록**한다 — 이름·주소·모델·API 키(없어도 된다) | 요청 원문, A.1-1 |
| FR-1101 | **삭제**한다. 그 LLM으로 한 대화는 남아 읽히고, 이어 물을 때는 다른 LLM을 고른다 | 지우면 즉시 못 쓴다(B절). 대화까지 지우면 사용자의 기록이 관리 작업에 딸려 사라진다 |
| FR-1102 | API 키는 **암호화해 저장**하고 화면·API 응답·로그·감사로그에 **다시 내보내지 않는다.** 화면은 "키 있음/없음"만 | 쟁점 2 |
| FR-1103 | 마스터 키가 없으면 **키가 있는 등록을 거부한다**(400, 까닭을 말한다). 키 없는 등록은 된다. 저장된 키를 풀 수 없으면 질문·연결 확인이 그렇게 말한다 | 조용히 평문으로 넣거나 조용히 실패하지 않는다 |
| FR-1104 | 주소는 `http(s)`만, **사용자 정보(`user:pass@`)·질의·조각을 받지 않는다.** 끝의 `/`는 뗀다 | 키가 주소에 섞여 화면·감사로그에 나가는 길을 막는다. 판정은 화면과 서버가 같은 함수를 쓴다 |
| FR-1105 | **연결 확인** — 서버가 `GET {주소}/models`를 불러 모델 목록과 "등록한 모델이 그 안에 있는가"를 보여 준다. 등록하면 화면이 곧바로 한 번 부른다 | 등록이 맞았는지 질문을 해 보기 전에 안다 |
| FR-1106 | 등록·삭제를 감사로그에 남긴다 (`llm.provider.create`·`llm.provider.delete`). 이름·주소·모델·키 유무 | 6절 관리자 작업. 어느 서버로 업무 내용이 나갔는지 되짚을 수 있어야 한다 |
| FR-1107 | 일반 사용자에게는 **이름과 모델만** 보인다 | 주소는 사내 호스트 정보다 |
| FR-1108 | 이름은 유일하다. 같은 이름이면 409 | 같은 이름에 다른 주소가 조용히 무시되면 관리자가 틀린 것을 믿는다(템플릿의 멱등과 다른 판단) |

| # | 요구 | 근거 |
|---|---|---|

| FR-1117 | 질문과 답은 **앱 로그에 남기지 않는다** | 7절 로그 규칙 — 문서 본문과 같은 수준 |
| FR-1118 | 질문마다 감사로그 `llm.ask` — 누가·어느 LLM·어느 대화·글자 수·토큰 수·결과·걸린 시간. **내용은 남기지 않는다** | A.1-8 |
| FR-1119 | Qwen3의 **생각 과정**은 접어서 보여 주고 저장하지 않으며 다음 질문에 넣지 않는다. 답 앞의 `<think>…</think>`도, 별도 필드(`reasoning_content`·`reasoning`)도 같다 | A.1-3 |
| FR-1120 | LLM 쪽 오류는 **까닭을 말한다** — 닿지 않는다·시간 상한·모델 서버가 거절(그 메시지를 줄여서). 문맥보다 긴 대화는 "새 대화를 시작한다"로. **몰래 자르지 않는다** | 조용히 앞부분을 잘라 보내면 사용자는 LLM이 앞 대화를 잊은 까닭을 모른다 |

### C.3 지시문 — 시스템 프롬프트 (FR-1125 ~ FR-1129)

## D. 설계

### D.1 요청의 길

```
브라우저 ──POST /api/llm/ask {질문}──▶ api ──POST {주소}/chat/completions (stream)──▶ 사내 LLM (vLLM)
   ◀─── NDJSON 한 줄씩 ─────────────── │ ◀─── SSE  data: {조각} … data: [DONE] ────────────
        delta · thinking · ping · end   │
                                        └─ 끝나면 한 트랜잭션: 대화·질문·답 저장 + 상한 정리 + 감사 llm.ask
```

- **확인은 흘려보내기 전에 한다.** 입력 검증·LLM·대화·지시문의 주인 확인·동시 질문·키 풀기는 여기서 실패하면 보통의
  HTTP 오류(400·404·409)다. 그 뒤 `200`과 머리말을 먼저 보내고 LLM을 부른다 — **LLM 쪽 실패는 흐름 안에서** `end`로 말한다.
- 머리말: `Content-Type: application/x-ndjson`, `Cache-Control: no-store`, **`X-Accel-Buffering: no`**. nginx는 이 머리말을
  보고 그 응답만 버퍼링하지 않는다 — `deploy/nginx.conf`에 위치 블록을 늘리지 않는다(버퍼링 판단을 한 곳에 둔다).
- 줄의 종류는 넷이다 (`packages/shared`의 LLM 계약, 서버와 화면이 같은 타입을 쓴다).

  | 줄 | 뜻 |
  |---|---|
  | `{"type":"delta","text":…}` | 답의 조각 |
  | `{"type":"thinking","text":…}` | 생각 과정의 조각 — 저장하지 않는다 |
  | `{"type":"ping"}` | 살아 있음. 15초 동안 아무것도 안 보냈으면 보낸다 (FR-1115) |
  | `{"type":"end","status":…,"saved":…,"conversationId":…,"evicted":…,"message":…}` | **마지막 한 줄.** `status`는 `done`·`stopped`·`failed` |

  `end` 없이 흐름이 끊기면 화면은 "연결이 끊겼다"로 본다.
- **중지는 따로 부른다** — `POST /api/llm/stop`. 화면이 연결을 끊는 대신 서버에 멈추라고 하므로, 서버가 저장한 결과를 `end`로
  끝까지 받는다(새 대화의 식별자도). 브라우저가 창을 닫아 연결이 끊겨도 서버는 LLM 요청을 끊고 거기까지를 저장한다.

### D.2 LLM에 보내는 것 — OpenAI 호환 형식

```
POST {주소}/chat/completions
Authorization: Bearer {API 키}          ← 키가 있을 때만
{ "model": "{모델}", "messages": [ … ], "stream": true, "stream_options": { "include_usage": true } }
```

- `messages` = (그 대화의 지시문이 있으면) `system` 하나 + 앞 이력(질문과 **생각 과정을 뺀** 답) + 이번 질문.
  빈 답(중지돼 글자가 없던 것)은 이력에 넣지 않는다.
- 받는 것: `data: ` 줄마다 JSON, `data: [DONE]`으로 끝. `choices[0].delta.content`가 답, `delta.reasoning_content`·
  `delta.reasoning`이 생각 과정(vLLM의 reasoning parser를 켠 경우), 마지막 조각의 `usage`가 토큰 수.
  reasoning parser를 켜지 않은 서버는 답 앞에 `<think>…</think>`를 그대로 흘린다 — **답의 맨 앞에서만** 그것을 생각 과정으로
  떼어 낸다(가운데의 `<think>` 글자는 답이다. 예: HTML 태그를 묻는 질문).
- **넘겨주기(redirect)를 따르지 않는다.** 따르면 키가 등록하지 않은 곳으로 간다.
- 응답 크기에 상한을 둔다 — 답은 `LLM_LIMITS.answerMaxChars`, 생각 과정도 같은 상한, 모델 목록 응답은 1MB.
- 오류 본문은 두 모양을 다 읽는다 — `{"object":"error","message":…}`(vLLM)과 `{"error":{"message":…}}`(OpenAI). 메시지를
  300자로 줄여 화면에 말한다(FR-1120). **로그에는 상태 코드만** 남긴다 — 남의 응답이라 무엇이 들었는지 모른다(`apps/api/src/mail/http.sender.ts`와 같은 판단).

### D.3 몰래 자르지 않는다 (FR-1120)

앞 이력을 전부 보낸다. 대화가 모델의 문맥보다 길어지면 LLM 서버가 거절하고, 화면은 그 까닭과 함께 **"새 대화를 시작한다"**를
말한다. 이력을 앞에서 잘라 보내는 길은 고르지 않았다 — 자르면 LLM이 앞 대화를 잊는데 사용자는 그 까닭을 모른다.
대화 하나의 메시지 수에도 상한(`LLM_LIMITS.messagesPerConversation`)을 둔다 — 문맥이 큰 모델에서 대화 하나가 끝없이 자라지 않게.

### D.4 API 키 암호화 (FR-1102·1103)

```
저장:  v1.{IV}.{태그}.{암호문}      (각 base64url)
       AES-256-GCM · IV 12바이트(요청마다 새로) · 부가 데이터(AAD) = "llm_providers:{행 id}"
마스터 키: WF_LLM_MASTER_KEY = 32바이트를 base64(url)로 적은 것 (openssl rand -base64 32)
```

- **AAD에 행 id를 묶는다.** DB를 만질 수 있는 사람이 암호문을 다른 행으로 옮겨 붙이면 풀리지 않는다.
- 마스터 키의 모양은 **기동할 때** 본다(32바이트가 아니면 기동 실패). 비어 있으면 키 없는 LLM만 등록된다(FR-1103).
- **마스터 키를 바꾸면 저장된 키를 풀 수 없다.** 그때 질문·연결 확인은 "API 키를 풀 수 없다 — 지우고 다시 등록한다"를 말한다.
  키를 다시 넣는 별도 화면은 두지 않았다 — 등록·삭제만 달라는 요청이고, 지우고 다시 등록하면 대화는 남는다(FR-1101).
- 키는 요청을 보낼 때만 풀어 메모리에 잠깐 둔다. 응답·로그·감사로그 어디에도 싣지 않는다. 감사로그의 비밀 거르기
  (`apps/api/src/audit/audit.service.ts`의 `SECRET_KEYS`)에 `api_key`·`apiKey` 모양을 더한다 — 실수로 실어도 떨어지게.

### D.5 보관 규칙 (FR-1130 ~ FR-1139)

`llm_conversations`의 세 시각이 규칙의 전부다.

| 열 | 뜻 |
|---|---|
| `updated_at` | 마지막 질문 시각 — 목록 순서 |
| `retain_from` | **보존 기간을 세는 기준.** 질문하면 지금, 고정을 풀면 지금 (A.1-5) |
| `pinned_at` | 고정한 시각. 있으면 보존 기간을 세지 않는다 |

- **만료** = `pinned_at IS NULL AND retain_from < now() - N일`. 목록·열기·이어 묻기가 이 조건으로 거르고(FR-1137), 한 시간마다
  앱이 지운다(FR-1136). 지우면 메시지도 함께 지워진다(`ON DELETE CASCADE`).
- **저장**은 한 트랜잭션이다 — 그 사람의 advisory lock → 대화 만들기·고치기 → 질문·답 넣기 → 개수가 M을 넘으면 고정하지 않은 것
  중 `retain_from`이 가장 오래된 것부터 지우기 → 감사 `llm.ask`. **잠금이 없으면** 두 탭에서 동시에 새 대화를 저장할 때 둘 다
  "아직 100개"로 보고 101개가 된다.
- **K < M이 늘 성립하므로** 지울 것이 늘 있다 — 고정만으로 M이 찰 수 없다. 관리자가 M을 줄이면 다음 저장에서 넘는 만큼 지운다.
  K를 지금 고정 수보다 낮추면 이미 고정한 것은 그대로 두고 새 고정만 막는다(풀지 않는다 — 사람이 한 설정을 관리 작업이 조용히
  되돌리지 않는다).
- **저장하는 때**: 답에 글자가 있을 때만(끝남·중지·실패 모두). 글자가 하나도 없으면 아무것도 저장하지 않고 화면은 질문을 입력칸에
  되돌린다 — 빈 대화가 상한을 먹지 않게.
- 이어 묻는 사이에 그 대화가 지워졌으면(다른 탭에서 지움·만료) 저장하지 않고 그렇게 말한다.

### D.7 마크다운 변환 (FR-1142)

`packages/shared/src/document.ts`의 허용 목록을 그대로 쓴다. 목록 밖 노드는 통째로 빼고, 목록 밖 마크는 무시하되 글자는 남긴다
(`packages/shared/src/html.ts`와 같은 규칙).

| 문서 | 마크다운 |
|---|---|
| 제목 1~6 | `#`…`######` |
| 굵게 · 기울임 · 취소선 · 코드 | `**…**` · `*…*` · `~~…~~` · 백틱(안에 백틱이 있으면 더 긴 백틱) |
| 밑줄 | 표기가 없어 **글자만** 남긴다 |
| 링크 | `[글자](https://…)` 모양 — 허용 주소가 아니면 글자만 |
| 글머리·번호 목록 | `- ` · `1. `(시작 번호 유지). 안쪽 블록은 들여 쓴다 |
| 인용 | 줄마다 `> ` |
| 코드 블록 | 울타리 코드 블록, 언어 유지. 울타리는 안의 백틱보다 길게 |
| 가로줄 · 줄바꿈 | `---` · 줄 끝 `\` |
| 표 | GFM 표. 첫 줄이 머리. 칸 안의 `\|`는 이스케이프, 칸 안 블록은 공백으로 잇는다. 칸 합치기는 표기가 없어 첫 칸에 둔다 |

본문 글자의 마크다운 기호(`\` `*` `_` `` ` `` `[` `]` `~`, 줄 머리의 `#` `>` `-` `+` `숫자.`)는 이스케이프한다 — 문서의
`*` 한 글자가 붙여 넣은 곳에서 기울임이 되지 않게.

## E. 데이터 모델 (`0009`)

```sql
llm_providers(
  id            uuid PRIMARY KEY,               -- 앱이 만든다 (키의 AAD에 묶기 위해)
  name          text NOT NULL UNIQUE,
  base_url      text NOT NULL,                  -- http(s)://…/v1, 끝 '/' 없음
  model         text NOT NULL,
  api_key_enc   text,                           -- D.4. NULL = 키 없음
  created_by    uuid NOT NULL REFERENCES users(id),
  created_at    timestamptz NOT NULL DEFAULT now()
)
llm_prompts(
  id uuid PRIMARY KEY, user_id uuid NOT NULL REFERENCES users(id),
  name text NOT NULL, content text NOT NULL, created_at, updated_at,
  UNIQUE (user_id, name)
)
llm_conversations(
  id uuid PRIMARY KEY, user_id uuid NOT NULL REFERENCES users(id),
  title text NOT NULL,
  provider_id uuid REFERENCES llm_providers(id) ON DELETE SET NULL,   -- FR-1101
  prompt_name text, system_prompt text,        -- 시작할 때의 지시문 복사본 (FR-1127)
  pinned_at timestamptz, retain_from timestamptz NOT NULL, created_at, updated_at
)
llm_messages(
  id uuid PRIMARY KEY,
  conversation_id uuid NOT NULL REFERENCES llm_conversations(id) ON DELETE CASCADE,
  role text NOT NULL CHECK (role IN ('user','assistant')),
  content text NOT NULL,
  model text,                                   -- 답한 모델
  status text NOT NULL CHECK (status IN ('done','stopped','failed')),
  created_at timestamptz NOT NULL
)
```

- 대화의 메시지는 대화와 수명이 같아 `CASCADE`다(`page_realtime`과 같은 판단). 사용자·LLM을 가리키는 것은 CASCADE가 아니다 —
  계정을 앱에서 지우는 경로는 없고, LLM을 지우면 대화는 남아야 한다(`SET NULL`).
- 새 감사 종류: `llm.provider.create` · `llm.provider.delete` · `llm.ask` · `llm.conversation.purge` (`AUDIT_ACTIONS`).

| 메서드 | 경로 | 권한 | 하는 일 |
|---|---|---|---|

## I. 설정 항목

환경변수 (`.env.example` · `deploy/compose.yml`과 같은 커밋):

| 키 | 기본값 | 무엇 |
|---|---|---|
| `WF_LLM_MASTER_KEY` | (없음) | API 키를 암호화하는 마스터 키. 32바이트 base64(url). 비면 키 없는 LLM만 등록된다 (D.4) |
| `WF_LLM_TIMEOUT_MS` | `600000` | 답 하나의 시간 상한 (FR-1115). 10초~1시간 |

운영 정책값 (DB `settings`, 관리 화면 "운영 설정" — `packages/shared/src/policy.ts`):

| 키 | 기본값 | 범위 | 무엇 |
|---|---|---|---|
| `llmRetentionDays` | 7 | 1~365 | 고정하지 않은 대화의 보존 기간 N (FR-1131) |
| `llmConversationMax` | 100 | 1~1000 | 사람마다 대화 수 M, 고정 포함 (FR-1132) |
| `llmPinnedMax` | 20 | 0~999, **M 미만** | 고정 수 K (FR-1133·1134) |

설계 고정값 (`packages/shared/src/constants.ts`의 `LLM_LIMITS`): 질문 10만 자, 답 20만 자, 대화 하나 200메시지, 지시문 2만 자·
사람마다 50개, 이름 80자, 제목 40자, 살아 있음 15초, 정리 1시간, 연결 확인 10초.

**켜고 끄는 환경변수를 두지 않았다.** 끄는 길은 관리 화면에서 LLM을 지우는 것이다 — 즉시 먹고 감사로그에 남는다. 스위치를 하나
더 두면 "켜져 있는데 등록이 없다"와 "등록은 있는데 꺼져 있다"가 따로 생긴다.

## K. 구현 순서

1. A등급 — 공유 계약(`llm.ts`·`markdown.ts`·정책값)과 api `llm/domain` 넷. **테스트 먼저**
2. 마이그레이션 `0009_llm` + 감사 종류 + 환경변수 셋(`.env.example`·`deploy/compose.yml`·이 표)
3. 서비스·어댑터 — 가짜 LLM 서버로 통합 시험(실제 PostgreSQL)
4. 화면 — 흐름 상태 기계 → 질문 화면 → 지시문 → 관리 화면 → 복사 버튼, 컴포넌트 시험
5. E2E — 모의 LLM 서버(Playwright 쪽에서 띄운다): 등록 → 지시문 → 흘러나오는 답 → 고정 → 이어 묻기 → 중지 → 복사해 붙이기
6. 컨테이너 — 이미지 빌드, **nginx를 거친 흐름**(NFR-101), 이미지 크기
7. 검증기록 → 검토(자체 점검·코드 리뷰·보안 검토·문서 정합성) → 학습가이드·장애대응·운영이관·반입 → PR
