# 기능 백로그

- 용도: 들어온 기능 요청을 **사용자의 말 그대로** 받아 적고, 크기와 어느 Phase의 일인지를 판정해 둔다
- 절차: [`CLAUDE.md`](../CLAUDE.md) 1.4절. **Claude는 크기와 영향만 알려주고, 지금 할지는 사용자가 정한다**
- 작성일: 2026-09-16 / 작성 LLM: Claude Opus 5

> **왜 이 문서가 있는가.** 기능 요청은 Phase 순서와 무관하게 온다. 바로 만들면 진행 중인 Phase의 검증이 반쪽이 되고, 안 적으면 요청 자체가 사라진다. 적어 두고 순서만 정하면 둘 다 피할 수 있다. **백로그에서 오래 기다리는 것은 손실이 아니다. 적어 두지 않은 요청만 사라진다.**

## 1. 크기 표기

| 표기 | 뜻 | 예 |
|---|---|---|
| **S** | 한 층만 만진다 | 화면 문구·버튼 위치·정렬 순서 |
| **M** | 두 층 이상을 만진다 | 새 목록 화면 + 그 목록을 주는 API |
| **L** | 데이터 구조가 바뀐다 | 새 테이블이나 새 컬럼이 필요하다 |

L은 되돌리기 어렵다. 운영 데이터가 이미 있으면 구조 변경에 별도 절차가 붙는다. 어느 층을 만지는지 판정하는 기준은 [`docs/설계서_Architecture.md`](설계서_Architecture.md) 11절이다.

## 3. 열린 요청

### F-010 · Windows 체험에서 나온 개선 10가지 (PC 화면·UI 전면·비밀번호·알림·감사 로그 레벨) · 접수 2026-09-28

F-009의 묶음(체험 가이드 10절)을 사용자가 자기 Windows에서 써 보고 준 것이다. 원문 그대로 적는다.

> 윈도우버전 보면서 개선사항
> 1. 비밀번호 변경시 기존 비밀번호 입력칸과 새로운 비밀번호 명확하게 구분되어야하며, 새로운 비밀번호 입력칸 외에 새로운 비밀번호 확인칸이 또 있어야 함. 기존 비밀번호와 새로운 비밀번호 입력값이 동일하다면 동일해서 안된다고 표시해줘야한다. 새로운 비밀번호  입력칸의 값과 확인칸의 값이 불일치하면 불일치하다고 표시해줘야하고, 비밀번호 옆에 눈모양 표시가 있어서 기본은 눈을 감은 모양이고 그때는 마스킹처리되어야 하며, 눈모양을 클릭했을 때 눈이 떠지고, 마스킹된값이 plain text로 보여져야함.
> 2. 화면이 모바일에서 쓰는 것처럼 굉장히 좁음. PC에서 사용하기 때문에 PC 웹사이트 화면에 최적화되어야함.
> 3. UI는 confluence나 웹어워드코리아 2025 수상작에서 이 소프트웨어와 성향이 맞는 것을 찾아서 전체 적용할 것. 즉 일부분(홈, 메인)만 적용되는게 아니라 모든 페이지가 다 UI가 맞게 적용되어야 함.
> 4. 페이지 편집에는 입력하는 창이 보여야함. 입력하는 창 부분이 '구분'되어야 함.
> 5. 댓글도, 댓글 쓰는 '창'과 그 외가 구분되어야함. 심지어 댓글 쓰여지지도 않음.
> 6. 뭔가 페이지마다 html 구조가 안잡혀 있는 부분이 있음. 예를들어 LLM연결 페이지의 '등록' 쪽을 보면, 이름+입력칸+주소+입력칸+모델+입력칸 이게 하나로 쭈욱 이어져있음. UI/UX가 엉망임. 당연히 줄 구분이나 항목 구분이 잘되어야함. 이건 3번에 따라서 맞게 잘 수정하기 바람.
> 7. 시스템 관리자가 아이디를 찾을 수 있는 방법도 도입되어야 함. 최소 가이드라도 있어야함. 아이디 찾기 옆에 '시스템 관리자 아이디 찾기'나 '관리자' 버튼을 넣어서 별도 페이지 구성할 것.
> 8. 관리자 아닌 사용자가 패스워드 초기화 요청시 시스템 관리자가 알 수 있는 방법이 없음. 알림에도 내용이 안들어와있음. 시스템 관리자, 관리자, 사용자 모두 접속시 초기 화면 옆에 알림이 들어오면 보여지는 알림창 같은게 있어야 할듯. 아니 모든 화면에서 알림이 들어오면 알림이 표시되는 영역이 있어야 함.
> 9. 시스템 관리자 비밀번호 변경 페이지에서 뒤로 가기나 홈으로 가기 버튼이 없음(다른 사용자도 그런지?). 이 버튼과 기능 넣을 것.
> 10. 감사 로그는 데이터가 엄청 많이 쓰여질 것 같음. 이거 감사 로그 레벨을 조정할 수 있게 할것. 시스템 관리자가 감사로그 화면에서 감사 로그 레벨을 일반적인 로그 레벨 단계로 표시해서 지정하도록 할것. 예를 들어, 모든 행위를 기록하는 레벨과, 사용자들 로그인/로그아웃 기록하는 레벨, 사용자들이 글쓰고 수정하고 하는 엑션을 기록하는 레벨이 단계적으로 존재해야함.

### F-009 · Docker 없이 Windows에서 받아서 풀고 바로 띄워 본다 · 접수 2026-09-28

Phase 15 진행 중에 들어왔다. 원문은 `docs/prompts/phase15/scope.md`.

> 인터넷이 되는 Windows에서 써보기(체험) 에 대해서 수정이 필요해.
> 현재 Windows 환경은 Docker를 사용할 수 없어. 클라우드 관리자가 이중 가상화를 막아놓았어.
> main 과 별도로 그냥 윈도우 로컬에서 실행해보고 결과를 볼 수 있는 방식으로 만들어볼 수 없어?

체험 가이드의 "가. Node로 직접" 길도 Docker·가상화 없이 뜬다(F-006). 다만 Node·pnpm·Git을 설치하고 `.env`를 고치고 창을 두 개 띄워야 한다. 사용자가 고른 것은 **받아서 푸는 묶음**이다 — Node·앱·체험용 데이터베이스를 zip 하나에 담는다. 풀고 `시작.cmd`를 누르면 첫 비밀번호가 보이고 브라우저가 열린다. 순서는 **Phase 15를 마친 뒤**다.

## 5. 요청을 넣는 방법

그냥 말씀하시면 된다. "이런 게 있으면 좋겠다" 정도로 충분하다. 제가 여기에 원문을 적고, 어느 단계의 일이고 얼마나 큰지, 기존 동작 중 무엇이 바뀌는지를 알려 드린다.

급한 요청도 적는 것이 먼저다. 다만 **장애와 보안 사안은 예외**로 진행 중인 작업을 멈추고 먼저 처리한다.
