# P14 설계서 — Spaces (페이지 트리를 화면에서 · 스페이스를 화면에서 관리)

Phase 14는 기능백로그의 **F-007**(페이지 트리에서 하위 페이지를 만들고 옮긴다)과 **F-008**(관리자가 화면에서 스페이스를 관리한다)이다. 둘 다
**서버 기능은 Phase 2·4에 있는데 누를 화면이 없다** — Phase 13에서 사용자 가이드를 쓰다가 코드에서 나왔다. 요청 원문은
`docs/prompts/phase14/scope.md`, 요구사항 번호는 **FR-1500**, 비기능은 **NFR-140**부터다.

선행: [`docs/P2_설계서_Page.md`](P2_설계서_Page.md) FR-346 · [`docs/P4_설계서_Admin.md`](P4_설계서_Admin.md) FR-530·532·537·538 ·
구조: [`docs/설계서_Architecture.md`](설계서_Architecture.md)

> **경로에 백틱이 없는 것은 아직 만들지 않은 것이다** (4.1절). 만들면 붙인다.

## A.1 묻지 않고 정한 것 — 근거와 되돌릴 조건

| # | 정한 것 | 근거 | 되돌릴 조건 |
|---|---|---|---|
| 1 | 옮기기는 **고르는 칸**으로 한다 — 새 부모와 자리(맨 앞, 또는 어느 페이지 다음)를 고른다. 트리에서 끌어 옮기기는 두지 않는다 | 끌어 옮기기는 키보드로 할 수 없고, 어디에 떨어지는지 눈으로만 가린다. 고르는 칸은 E2E로 그대로 확인된다 | 끌어 옮기기를 원한다는 요청이 오면 |
| 2 | 자리는 **형제 가운데 몇 번째**(0부터)다. 서버가 새 부모 아래 형제의 자리를 처음부터 다시 매긴다 | 예전 API는 받은 자리 값을 그대로 적었다 — 같은 값이 여럿이면 순서가 만든 시각으로 갈려 "이 페이지 다음"을 지킬 수 없다. 부르는 곳이 시험뿐이라(화면이 없었다) 뜻을 굳혀도 깨지는 것이 없다 | — |
| 3 | 다른 스페이스로는 옮기지 않는다 | P2가 막았다(`checkMove`의 `cross-space`). 스페이스를 넘으면 읽을 수 있는 사람(Crew)이 달라진다 | — |
| 4 | 하위 페이지는 **스페이스 화면의 새 페이지 칸**에서 부모를 골라 만든다. 페이지 보기의 **하위 페이지 만들기**는 그 칸으로 부모를 골라 둔 채 간다(`?parent=`) | 만드는 곳을 하나로 둔다 — 템플릿 고르기도 그 칸에 있다 | — |
| 5 | 관리 콘솔에 **스페이스** 화면을 하나 더한다 — 모든 스페이스와 분류 | 관리자가 Crew가 아닌 스페이스까지 한곳에서 보는 곳이 없었다(P4 FR-530). 분류는 모든 스페이스가 함께 쓰는 것이라 같은 화면에 둔다 | — |
| 6 | 스페이스 화면에는 **관리** 칸을 둔다 — 그 스페이스를 관리하는 사람(만든 사람·owner·관리자)에게만 보인다 | 개인 스페이스와 팀 스페이스의 주인이 자기 스페이스를 관리한다(권한은 `spaceAccess`가 이미 정했다). 보이는 조건은 응답의 `access`다(P2 FR-345) | — |
| 7 | 지우기는 **확인을 한 번 더** 받는다. 지운 스페이스는 휴지통에서 되살린다(관리자) | 사용자 정지(P13)와 같은 모양. 휴지통은 P3·P4에 있다 | — |

## C. 요구사항

### C.1 페이지 트리 (FR-1500 ~ FR-1505, F-007 · P2 FR-346)

| # | 요구사항 | 근거 |
|---|---|---|
| FR-1500 | 새 페이지를 **다른 페이지 아래에** 만든다 — 스페이스 화면의 새 페이지 칸에서 위치(맨 위 또는 그 스페이스의 페이지)를 고른다. 페이지 보기의 **하위 페이지 만들기**는 그 칸으로 부모를 골라 둔 채 간다 | 새 페이지는 늘 맨 위 단계에 생겼다 — 계층을 화면에서 만들 수 없었다 |
| FR-1501 | 페이지를 **옮긴다** — 페이지 보기의 **옮기기**에서 새 부모(맨 위 또는 같은 스페이스의 다른 페이지)와 자리(맨 앞, 또는 어느 페이지 다음)를 고른다. 자기 자신과 그 아래는 고를 수 없다 | P2 FR-346. API와 감사(`page.move`)는 있는데 부를 곳이 없었다 |
| FR-1502 | 옮긴 자리는 **형제 가운데 몇 번째**다 — 서버가 새 부모 아래 형제의 자리를 처음부터 다시 매긴다. 형제 수보다 크면 맨 뒤다 | 예전 API는 받은 값을 그대로 적어 같은 자리가 여럿 생겼다(A.1-2) |
| FR-1503 | 한 스페이스의 옮기기는 **한 번에 하나씩** 한다 | 둘이 동시에 옮기면 다시 매긴 자리가 서로 겹친다 |
| FR-1504 | 옮길 수 없는 자리(자기 아래, 깊이 10을 넘음)는 서버가 거절하고 **화면이 그 까닭을 그대로 보인다** | 판정은 A등급 `checkMove`(P2)다. 화면은 규칙을 다시 만들지 않는다(P2 FR-345) — 자기와 그 아래를 목록에서 빼는 것은 편의다 |
| FR-1505 | 하위 페이지 만들기·옮기기는 **쓸 수 있는 사람에게만** 보인다(`access.canWrite`) | P2 FR-345 |

## D. 설계

### D.1 자리 다시 매기기 (FR-1502·1503, NFR-140)

- **`placeAt`**(A등급, `apps/api/src/pages/domain/tree.ts`) — 지금 순서의 형제 ID 목록과 옮기는 페이지, 자리(0부터)를 받아 새 순서를 돌려준다.
  옮기는 페이지가 목록에 있으면 먼저 뺀다(같은 부모 안에서 옮기기). 자리는 0과 형제 수 사이로 자른다. 조회하지 않는다 — `checkMove`와 같은 판단.
- **서비스**(`PagesService.move`) — 한 트랜잭션에서:
  1. 스페이스마다의 잠금(`pg_advisory_xact_lock(hashtext('page-tree:<스페이스 id>'))`) — 같은 스페이스의 옮기기가 줄을 선다(FR-1503).
     잠금 모양은 이 저장소의 다른 줄 세우기와 같다(`users:last-root`, `llm:<사용자>`).
  2. 쓰기 권한과 부모 판정(`checkMove`) — 그대로.
  3. 새 부모 아래의 형제(자기 제외, 지워지지 않은 것)를 화면과 같은 순서(`position`, 만든 시각)로 읽는다.
  4. `placeAt`으로 새 순서를 만들고, **자리가 바뀐 줄만** 고친다. 옮긴 페이지는 부모도 함께.
- 옛 부모 아래에 남은 형제는 그대로 둔다 — 자리에 틈이 생겨도 순서는 같다. 새 페이지는 지금처럼 형제의 맨 뒤(`max + 1`)에 붙는다.

### D.2 화면 — 페이지 트리 (FR-1500·1501·1504·1505)

- **트리 펼치기**(apps/web/src/components/pageTree.ts, 순수 함수) — 서버가 준 목록(부모·자리 순서)을 들여쓰기 깊이와 함께 한 줄로 펼친다.
  "자기와 그 아래"를 구한다. 스페이스 화면의 트리, 위치 고르기, 옮기기 칸이 이것 하나를 쓴다.
- **스페이스 화면** — 새 페이지 칸에 **위치**(맨 위 / 들여 쓴 페이지 목록). 주소의 `?parent=<페이지>`가 있으면 그것을 골라 두고 제목 칸으로 간다.
- **페이지 보기** — 쓸 수 있으면 **하위 페이지 만들기**(→ `/spaces/<스페이스>?parent=<이 페이지>`)와 **옮기기**.
  옮기기 칸(apps/web/src/components/MovePage.tsx)은 새 부모(맨 위 + 자기와 그 아래를 뺀 페이지들)와 자리(맨 앞 / "<형제> 다음")를 고르고
  `PATCH /api/pages/:id/move`를 부른다. 거절되면 서버의 까닭을 그 칸에 보인다. 옮기면 트리가 있는 스페이스 화면으로 간다.

### D.3 화면 — 스페이스 관리 (FR-1510 ~ FR-1515)

- **스페이스 화면의 관리 칸**(apps/web/src/components/SpaceManage.tsx) — `access.canChangeStatus`면 이름·설명·분류(쓸 수 있을 때)와
  중지·다시 쓰기, `access.canDelete`면 지우기(확인 → `DELETE` → 스페이스 목록). 분류 목록은 `GET /api/categories`.
- **Crew** — 넣을 때 역할 고르기(editor·viewer), 줄마다 역할 고르기(`PATCH /api/spaces/:id/members/:userId`). owner 줄은 바꾸지 않는다.
- **관리 콘솔의 스페이스 화면**(apps/web/src/pages/admin/AdminSpacesPage.tsx) — 찾기 칸(입력을 멈추면 찾는다)·상태 고르기 →
  `GET /api/spaces?scope=all&q=&status=&limit=500`. 줄마다 이름(열기)·키·종류·상태·분류·Crew 수·만든 사람과 동작(중지·다시 쓰기, 중지된
  것은 지우기). 500개를 채우면 "찾기로 좁힌다"를 보인다. 아래에 분류 칸(만들기·이름 바꾸기·지우기).
- **스페이스 목록 화면**의 관리 메뉴에 **스페이스 관리**(`space.manage`일 때).

### D.4 서버 — 모든 스페이스의 찾기 (FR-1514)

`spaceListQueryDto`에 `q`(앞뒤 공백을 자른 1~100자)와 `status`를 더한다. `q`는 이름·키의 `ILIKE` 부분 일치 — `%`·`_`는
`apps/api/src/common/like.ts`로 막는다(P13 사용자 찾기와 같다). 두 조건은 어느 범위(`scope`)에서나 먹는다.

## F. API 계약

| 경로 | 바뀜 |
|---|---|
| `PATCH /api/pages/:id/move` | `position`은 **형제 가운데 몇 번째**(0부터)다. 서버가 새 부모 아래 형제의 자리를 다시 매긴다. 형제 수보다 크면 맨 뒤 |

## G. 화면

- 스페이스 화면: 트리(들여쓰기), 새 페이지 칸의 **위치**, **관리** 칸, Crew의 역할 고르기.
- 페이지 보기: **하위 페이지 만들기**·**옮기기**.
- 관리 콘솔: **스페이스**(모든 스페이스 + 분류). 스페이스 목록 화면의 관리 메뉴에 그 이름.
