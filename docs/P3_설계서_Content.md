# A. 요구사항

## A.0 착수 시 확정한 쟁점 (2026-09-22)

| # | 쟁점 | 확정 | 근거 |
|---|---|---|---|
| 1 | **보류 2** — pg_trgm이 한글 2글자를 감당하나 | **재 본다.** 먼저 `pg_trgm`으로 만들고 **재현율과 p95를 실측**해 판정한다. 미달이면 pg_bigm 이미지를 반입 목록에 올린다 | 보류 2의 판정 방법 그대로. **재 보지 않고 미리 바꾸지 않는다** |
| 2 | **보류 3** — 첨부 바이러스 스캔(ClamAV)을 넣나 | **훅 지점만 둔다.** 스캔 구현은 하지 않는다 | 확인 필요 B(사내 보안 정책)가 열려 있다. 기본 가정은 "정책 문서 없음"이고, 보류 3은 그 경우 "훅 지점만"으로 정해 뒀다 |

| 4 | 같은 파일을 여러 번 올리면 | **내용 해시(SHA-256)로 한 벌만 저장**하고 메타데이터만 따로 둔다 | `CLAUDE.md` 6절 |

# 2. 검색

## 2.1 권한을 질의에서 거른다 (FR-403)

```sql
SELECT ... FROM pages p
  JOIN spaces s ON s.id = p.space_id AND s.deleted_at IS NULL
  LEFT JOIN space_members m ON m.space_id = s.id AND m.user_id = :me
 WHERE p.deleted_at IS NULL
   AND (:isAdmin OR m.user_id IS NOT NULL OR (s.kind = 'personal' AND s.created_by = :me))
   AND (p.title ILIKE :q OR p.search_text ILIKE :q)
```

**가져와서 거르지 않는다.** Phase 2에서 목록이 그 실수를 했다 — `limit`을 권한 필터 앞에 걸어
결과가 조용히 비었다 (자체 점검 #4-b).

## 2.2 보류 2를 어떻게 판정하나 (FR-407)

`pg_trgm`은 **3글자 조각**으로 인덱스를 만든다. 한글 2글자 질의(`검색`)는 조각이 하나도 안 되므로
**인덱스를 못 타고 전체 훑기**가 된다. 그래도 수천 행에서는 충분히 빠를 수 있다 — **재 봐야 안다.**

검증기록에 적을 것: 페이지 N건에서 2글자 질의 p95와 재현율. **p95 ≥ 1초 또는 재현율 < 1.0이면
보류 2를 발동**해 pg_bigm 이미지를 반입 목록에 올린다.

# 3. 첨부

## 3.1 경계

```ts
export interface StorageProvider {
  put(sha256: string, data: Buffer): Promise<void>;
  get(sha256: string): Promise<Buffer>;
  has(sha256: string): Promise<boolean>;
  delete(sha256: string): Promise<void>;
}
```

로컬 구현은 `WF_STORAGE_PATH/<앞2자>/<해시>`에 둔다. 한 디렉토리에 파일이 수만 개 쌓이지 않게
앞 두 자로 나눈다.

## 3.2 경로에 사용자 입력을 쓰지 않는다 (FR-412)

파일 이름은 **우리가 계산한 SHA-256 16진수**다. 원본 파일명은 DB에만 있고 다운로드 헤더로만
나간다. 업로드한 이름에 `../`가 있어도 경로에 닿지 않는다.

## 3.3 스캔 훅 (FR-418)

```ts
export interface AttachmentScanner {
  scan(data: Buffer, filename: string): Promise<{ ok: true } | { ok: false; reason: string }>;
}
```

기본 구현은 `{ ok: true }`를 낸다. **확인 필요 B가 답을 주면 여기에 ClamAV를 끼운다.**
훅 지점을 지금 두는 이유는, 나중에 넣을 때 호출부를 찾아 헤매지 않기 위해서다.
