## 1. 목적

Phase 1~6이 공유하는 기반을 확정한다.

각 Phase가 필요할 때마다 설정·상수·권한 판정·로거를 따로 만들면 서로 어긋난다. 예를 들어 화면이 자기 방식으로 권한을 판단하고 서버가 또 판단하면, 규칙 하나를 바꿀 때 두 곳을 고쳐야 하고 한 곳을 빠뜨리면 **버튼은 보이는데 누르면 403**이 된다. 공유되는 것을 먼저 확정해 이런 어긋남을 원천 차단한다.

또한 **폐쇄망 반입 경로를 맨 처음 뚫어 둔다.** 이미지 크기·의존성·네트워크 제약은 마지막에 드러나면 설계를 뒤집는다. 그래서 Phase 0의 완료 기준은 문서가 아니라 **Linux 서버에서 빌드한 이미지가 떠서 헬스체크에 응답하는 것**이다.

## 2. 배경 및 제약

- **개발 PC에 Docker가 없다** (Windows). 컨테이너 빌드는 별도 Linux 서버에서 하고, 개발 명령은 OS 무관해야 한다.
- **운영은 인터넷이 없다.** 런타임에 외부 자원을 참조하면 화면이 깨지거나 기동이 지연된다.
- **저장소가 공개다.** 사내 정보·시크릿이 섞이면 이력에서 지워야 한다. 기계 검사를 CI에 둔다.
- **프로토타입이 있다** (`exp/prototype`). 동작을 확인한 코드지만 요구사항·설계 문서가 없다. 근거를 먼저 세우고 승격한다.

## 4. 기능 요구사항

### 4.1 모노레포·빌드 기반

**FR-001.** pnpm 워크스페이스로 `apps/*`·`packages/*`를 구성하고, Node와 pnpm 버전을 `engines`·`packageManager`로 고정한다. 개발 PC와 컨테이너의 런타임이 달라 생기는 "여기선 되는데 저기선 안 되는" 상황을 막는다.

**FR-002.** pnpm 데이터(store·cache)는 저장소 안 `.local/` 아래에 둔다. 프로젝트와 같은 드라이브여야 하드링크가 동작한다. **설정 위치는 `pnpm-workspace.yaml`이다** — pnpm 12는 `.npmrc`의 pnpm 설정을 읽지 않는다(실측).

**FR-003.** 줄바꿈을 LF로 고정한다(`.gitattributes`). Windows에서 작성한 셸 스크립트·Dockerfile이 Linux에서 깨지지 않게 한다.

**FR-004.** 네이티브 모듈의 설치 스크립트는 명시적으로 허용한 것만 실행한다(`allowBuilds`). 임의 패키지의 postinstall이 도는 것을 막는다.

### 4.2 환경 설정 (`packages/shared/src/env.ts`, `apps/api/src/config`)

**FR-010.** 앱 환경변수는 모두 `WF_` 접두사를 쓴다. 다른 도구의 환경변수와 섞이지 않는다.

**FR-011.** 스키마는 **strict**다. `WF_`로 시작하는데 스키마에 없는 키가 있으면 **기동에 실패**한다. 오타 난 키나 코드가 읽지 않는 키를 즉시 드러낸다. 프로토타입 이전 사례에서 "설정 파일에 값은 있는데 코드가 읽지 않아 아무 일도 일어나지 않는" 문제가 반복됐다.

**FR-012.** 타입·범위가 맞지 않으면 기동에 실패한다. 포트에 문자열이 들어가는 일을 런타임 중간이 아니라 기동 시점에 잡는다.

**FR-013.** 빈 문자열 값은 미설정으로 취급하고 기본값을 쓴다. `.env`에 키만 남기고 값을 지운 경우를 자연스럽게 처리한다.

**FR-014.** `WF_ENV=production`에서 `WF_DB_AUTO_MIGRATE=true`를 **거부**한다. 설정 실수로 운영 DB가 기동과 함께 조용히 바뀌는 것을 막는다.

**FR-015.** `.env.example`의 키 집합과 스키마의 키 집합이 **같음을 테스트로 강제**한다. 키를 추가하고 예시 파일을 안 고치는 실수를 기계가 잡는다.

**FR-016.** `.env.example`에는 placeholder만 둔다. 실제 호스트명·시크릿을 넣지 않는다 (공개 저장소).

**FR-017.** 설정 로더는 `.env` 파일과 `process.env`를 함께 읽고 `process.env`를 우선한다. 컨테이너는 환경변수 주입, 개발은 파일이 편하다.

### 4.3 공유 계약 (`packages/shared`)

**FR-020.** 다음을 단일 정의하고 서버·클라이언트가 함께 쓴다: 역할 3종, 사용자 상태, 스페이스 종류·상태, Crew 역할, 감사 이벤트 종류, 문서 스키마 버전, 페이지 트리 최대 깊이, CSRF 헤더, 비밀번호 정책 기본값, 요청 제한 기본값.

**FR-021.** 문서(ProseMirror JSON) **검증기**를 제공한다. 허용 노드·마크·속성 목록 밖은 거부하고, 위반 위치를 알려준다. 링크는 `http(s)`·내부 경로·앵커만 허용한다. 노드 수·중첩 깊이 상한을 둔다.

**FR-022.** 문서에서 **검색용 평문을 추출**한다. 블록 경계는 줄바꿈으로 잇는다. 서버가 추출하므로 클라이언트가 보낸 텍스트를 믿지 않는다.

**FR-023.** 권한 판정 함수를 제공한다. 시스템 행위 판정(`can`)과 스페이스 접근 판정(`spaceAccess`), 역할 간 우열(`canAssignRole`·`canManageUser`). **기본 거부**이며 알 수 없는 역할은 아무 권한도 없다.

**FR-024.** 비밀번호 정책 판정 함수를 제공한다. 위반 사유를 **목록으로** 돌려준다. 화면이 "무엇이 부족한지"를 보여줄 수 있어야 한다.

**FR-025.** 보안 유틸을 제공한다: ID·email 마스킹, 임시 비밀번호 생성, 스페이스 식별자 생성. **난수 소스를 인자로 받는다** — 서버는 암호학적 난수를, 테스트는 결정적 수열을 넣는다.

**FR-026.** 임시 비밀번호는 정책을 **항상** 만족하고, 혼동 문자(0/O, 1/l/I)를 쓰지 않는다. 화면에서 읽어 옮겨 적는 값이다.

**FR-027.** API 요청 DTO와 응답 뷰 타입을 정의한다. 서버 검증과 클라이언트 타입이 한 정의에서 나온다.

### 4.4 DB 연결·마이그레이션·시드 (`apps/api/src/db`)

**FR-030.** PostgreSQL 연결 풀을 제공하고, 종료 시 정리한다. `WF_ENV=test`면 테스트 DB를 쓴다.

**FR-031.** 마이그레이션은 **SQL 파일**로 커밋하고 순서대로 적용한다. 이미 적용된 것은 건너뛴다(멱등).

**FR-032.** 마이그레이션 적용은 **별도 실행 가능**해야 한다. 운영 배포 절차가 기동과 분리된 단계로 실행한다.

**FR-033.** `settings` 테이블을 만든다. 운영 조절값의 저장 위치다.

**FR-034.** 시드는 멱등이다. 두 번 실행해도 결과가 같다. Phase 0 시드는 만들 것이 없으므로 **틀만** 두고 Phase 1에서 계정 시드를 넣는다.

### 4.5 헬스체크 (`apps/api/src/health`)

**FR-040.** `GET /api/health`는 **DB 질의까지 수행**하고 성공 시 `{status, db, time}`을 반환한다. 앱은 떴는데 DB를 못 쓰는 상태를 "정상"으로 보고하지 않는다.

**FR-041.** DB 연결 실패 시 503을 반환한다. 컨테이너 헬스체크가 이를 실패로 인식해야 한다.

### 4.6 로깅 (`apps/api/src/common`)

**FR-050.** 로그는 **stdout에 JSON 한 줄**로 출력한다. 컨테이너 환경에서 수집기가 가져가는 표준 방식이다. 파일에 직접 쓰지 않는다.

**FR-051.** 비밀번호·토큰·세션 ID·쿠키를 로그에 남기지 않는다(마스킹).

**FR-052.** Nest 프레임워크 로그도 같은 형식으로 나간다. 기동 로그만 형식이 달라 파싱이 깨지는 일을 막는다.

### 4.7 공통 요청 처리

**FR-060.** 요청 본문·쿼리는 zod 스키마로 검증하는 파이프를 통과한다. 실패는 400과 **위반 항목 목록**을 반환한다.

**FR-061.** 공개 엔드포인트용 **IP별 요청 제한** 가드를 제공한다. 단일 인스턴스 전제이며, 이중화 시 공유 저장소로 옮긴다.

**FR-062.** 보안 응답 헤더를 전역으로 붙인다: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`, (TLS일 때) HSTS.

**FR-063.** `/api/*` 응답은 `Cache-Control: no-store`. 해시 파일명 정적 자산만 `immutable` 캐시를 허용한다.

**FR-064.** 프록시 뒤에서 동작하므로 신뢰 프록시 설정을 둔다. `X-Forwarded-Proto`가 반영되지 않으면 리다이렉트·쿠키 보안 판정이 깨진다.

### 4.8 웹 셸 (`apps/web`)

**FR-070.** SPA를 빌드하고 api가 정적 서빙한다. 딥링크는 `index.html`로 폴백하되 `/api/*`는 제외한다.

**FR-071.** Phase 0의 화면은 **기동 확인 화면** 하나다. `/api/health` 결과와 버전을 보여준다. "브라우저에서 확인 가능한 증분"을 만든다.

**FR-072.** 외부 폰트·아이콘·스크립트를 참조하지 않는다. 시스템 폰트와 인라인 SVG만 쓴다.

### 4.9 스크립트

**FR-080.** `pnpm check:env` — Node·pnpm 버전, `.env` 존재와 스키마, 데이터 경로가 `.local/` 아래인지, 드라이브 여유, DB 연결, 마이그레이션 상태를 검사하고 전부 통과하면 마지막 줄에 `READY`를 출력한다. 하나라도 실패하면 종료 코드 1.

**FR-081.** `pnpm dev:db` — 임베디드 PostgreSQL을 `.local/pgdata`에서 기동한다. 최초 실행 시 초기화와 DB 생성까지 한다. 관리자 권한 셸에서는 PostgreSQL이 기동을 거부하므로 안내 메시지를 남긴다.

**FR-082.** `pnpm verify:docs` — 문서의 명령·경로·링크를 기계 검사한다. 검사 항목: ① `pnpm <script>`의 스크립트 실재 ② 백틱 안 저장소 경로 실재 ③ 마크다운 상대 링크 유효 ④ 표 열 수 불일치 ⑤ `deploy/*.sh` 실행 가능 ⑥ 코드블록 안 `pnpm` 명령의 스크립트 실재. 위반이 있으면 종료 코드 1.

**FR-083.** `pnpm test:e2e` — Playwright를 저장소 안 브라우저 경로로 실행한다. OS별 환경변수 문법을 문서에 노출하지 않는다.

**FR-084.** `pnpm check` — lint + typecheck + test + verify:docs를 한 번에 돌린다. 개발 PC가 CI와 **같은 검사**를 해야 "로컬은 통과했는데 CI가 실패"를 줄인다. CI는 같은 검사를 단계로 나눠 돌린다 (FR-091).

### 4.10 검사와 CI

**FR-090.** ESLint로 **import 경로 대소문자 불일치**를 잡는다. Windows는 대소문자를 구분하지 않아 Linux 빌드에서만 실패하는 유형이다.

**FR-091.** CI는 push·PR마다 `pnpm check`와 **같은 검사**(lint·typecheck·test·verify:docs)를 돌린다. CI에서는 한 줄로 묶지 않고 **관문마다 별도 단계**로 나눈다 — 어느 관문이 걸렸는지 로그를 뒤지지 않고 알기 위해서다. (정정 2026-09-16: 처음에는 "`pnpm check`를 돌린다"였다. CI 단계를 나눈 뒤 문구를 실제와 맞췄다.)

**FR-092.** CI에 **gitleaks**를 넣는다. 공개 저장소에 시크릿이 들어가는 것을 막는다.

**FR-093.** CI에서 **의존성 라이선스**를 검사한다. 허용: MIT·Apache-2.0·BSD·ISC·0BSD 등. GPL·AGPL·SSPL·상용은 승인 없이 금지.

**FR-094.** CI에서 **빌드 산출물의 외부 URL 참조**를 검사한다. 폐쇄망에서 깨지는 자산을 반입 전에 잡는다.

### 4.11 컨테이너·배포

**FR-100.** 멀티스테이지 Dockerfile로 app 이미지를 만든다. 런타임 스테이지에는 산출물과 production 의존성만 둔다.

**FR-101.** 컨테이너는 non-root로 실행하고 헬스체크를 포함한다.

**FR-102.** compose에 app·postgres·nginx를 정의하고 전부 `restart: unless-stopped`를 둔다. 재부팅 후 자동 기동이 되지 않아 "서비스가 내려간 것을 코드 문제로 오진"하는 일을 막는다.

**FR-103.** nginx는 TLS를 종단하고 `X-Forwarded-*`를 전달한다. 호스트 매핑 포트가 리다이렉트에서 유실되지 않게 한다. WebSocket 업그레이드를 프록시한다(Phase 6 대비). 업로드 상한은 첨부 상한과 맞춘다.

**FR-104.** `.dockerignore`로 `node_modules`·`.env`·`.local`·`docs`·`e2e`를 빌드 컨텍스트에서 제외한다.

### 4.12 에이전트·스킬

**FR-110.** `doc-consistency`(읽기 전용 문서 정합 검사), `self-reviewer`(결함 탐지) 에이전트와 `troubleshoot` 스킬을 정의한다.

**FR-111.** 설계 근거·모델 배정·실행 기록을 `docs/internal/설계서_Agents.md`에 남긴다. 정의 파일은 "무엇을 하라"만 담으므로, **왜 그 일을 맡기는지**가 저장소 안에 없으면 다음 담당자가 알 수 없다.

## 8. 리스크

| # | 리스크 | 대응 |
|---|---|---|
| 1 | 프로토타입 코드를 근거 없이 옮겨 문서와 코드가 따로 논다 | 모듈별로 "왜 이 형태인가"를 설계서에 쓰고, 쓸 수 없으면 가져오지 않는다 |
| 2 | Phase 0이 비대해져 기반이 아닌 기능까지 들어온다 | 3절 Out of Scope를 관문으로. 인증·스페이스·페이지는 넣지 않는다 |
| 3 | Linux 빌드가 개발 PC와 달라 늦게 실패한다 | 완료 기준에 넣어 **Phase 0 안에서** 확인한다. 실패하면 Phase 0을 닫지 않는다 |
| 4 | shared가 전 Phase DTO를 담아 Phase 진행 중 자주 바뀐다 | 바뀌는 것은 정상이다. 변경은 해당 Phase 문서에 정정 이력으로 남기고 테스트가 회귀를 막는다 |
| 5 | CI 도구(gitleaks·라이선스)가 오탐으로 관문을 무력화한다 | 예외는 파일로 관리하고 사유를 주석에 남긴다. **무시되는 관문은 없는 것보다 나쁘다** |
