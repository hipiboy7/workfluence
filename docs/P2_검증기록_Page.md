## 2. 인수 기준 검증

### 2.1 실호출 (HTTP)

```
POST /api/spaces            → 201 {"key":"WFHFUY5E","kind":"team","memberCount":1,...}
POST /api/pages             → 201 {"currentVersionNo":1,...}
PATCH /api/pages/:id (base=1) → 200, 현재 버전 2
PATCH /api/pages/:id (base=1) → 409 {"message":"다른 사용자가 먼저 저장했다. 최신 버전을
                                     불러와 다시 편집해야 한다","currentVersionNo":2,
                                     "baseVersionNo":1}
POST /api/pages/:id/versions/1/restore → 제목=첫 페이지, 현재버전=3
GET  /api/pages/:id/versions → v3(첫 페이지) · v2(수정됨) · v1(첫 페이지)
```

**복원해도 이력이 남는다** — v1·v2가 그대로 있고 v3이 새로 생겼다 (FR-325).

### 2.2 브라우저 (E2E)

```
팀 스페이스 생성 → Crew 추가(editor) → 페이지 작성 → 편집·저장(v2)
→ 다른 경로가 먼저 저장 → 저장 시도 → "다른 사람이 먼저 저장했다" 안내
→ 덮어쓰기 버튼 없음 확인 → v1 복원 → 버전 4
```

Crew가 아닌 사용자는 그 스페이스가 목록에 보이지 않고, 자기 개인 스페이스만 보인다.

## 3. 규칙 실호출 확인

| 항목 | 확인 | 결과 |
|---|---|---|
| 접근 판정 (FR-303) | 팀 스페이스에 Crew 아닌 사용자 | **404** (403이 아니다 — 존재를 알리지 않는다) |
| 중지 스페이스 (FR-306) | `canWrite` | `false`, `canRead`는 `true` |
| 개인 스페이스 (FR-305) | 남이 조회 | 404 |

| 스페이스 삭제 (FR-307) | Crew 2명일 때 소유자가 삭제 | 거부. 혼자일 때만 가능 |
| 개인 스페이스 자동 생성 (FR-309) | 승인 트랜잭션, 두 번 호출 | 하나만 생긴다 (멱등) |

| 다른 스페이스 (FR-327) | 남의 스페이스 페이지를 부모로 | `다른 스페이스의 페이지를 부모로 둘 수 없다` |
| 깊이 (FR-328) | 10단 아래에 하나 더 | `페이지 트리 깊이는 10을 넘을 수 없다` |
| 하위 있는 삭제 (FR-329) | | `하위 페이지가 있는 페이지는 삭제할 수 없다` |
| 재색인 (FR-333) | `search_text`를 비우고 재생성 | 복구됨 |
| 페이지 권한 (FR-331) | viewer가 저장 | 403 |

## 6. 확인하지 못한 것

| # | 확인 못 한 것 | 왜 | 언제 |
|---|---|---|---|
| 1 | 페이지 저장 p95 (NFR-22) | 부하 도구 없이 단건 호출만 했다. 체감은 즉시지만 **수치가 없다** | Phase 5 부하 테스트 |
| 2 | 트리 깊이 검사의 성능 | 깊이 10이면 최대 10회 조회 + 자손 높이 조회. 페이지가 많을 때를 재지 않았다 | Phase 5 |
| 3 | 여러 사람이 **실제로 동시에** 편집하는 상황 | 통합 테스트는 두 트랜잭션을 같은 프로세스에서 돌렸다. 여러 인스턴스는 보류 6 | Phase 5 |
| 4 | `kind`·`status`에 DB CHECK 제약이 없다 | 잘못된 값이 들어가면 판정이 조용히 기본 분기로 떨어진다. 코드에 주석으로 남겼다 | Phase 4 (상태가 늘 때) |
| 5 | 페이지 이동을 화면에서 하는 것 (FR-346) | API는 있고 테스트도 있지만 **트리에서 끌어 옮기는 UI는 만들지 않았다** | Phase 4 관리 화면과 함께 |

## 7. Phase 3 인계 사항

| 항목 | 내용 |
|---|---|
