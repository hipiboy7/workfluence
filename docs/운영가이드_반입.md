# 운영가이드 — 폐쇄망 반입

- 읽는 사람: **반입 당일 작업자.** 이 문서만 보고 처음부터 끝까지 할 수 있어야 한다
- 이 문서는 반입 묶음에 `반입절차.md`로 복사되어 함께 들어간다
- 작성일: 2026-09-22 (Phase 5)

> **인터넷이 없다.** 이미지를 받거나 패키지를 설치하는 단계는 이 문서에 하나도 없다.
> 그런 단계가 필요해졌다면 묶음이 잘못 만들어진 것이다 — 밖에서 다시 만든다.

---

## 0. 미리 확인할 것

| 확인 | 명령 | 기준 |
|---|---|---|
| 도커가 있고 부팅 시 뜬다 | `systemctl is-enabled docker` | `enabled` |
| 디스크 여유 | `df -h /` | **5GB 이상** |
| 묶음이 온전하다 | `pnpm release:verify <묶음>` | `통과` |

마지막 것이 가장 중요하다. **옮기는 중에 상한 묶음으로 시작하면 부분 반입이 되고,
그때는 무엇이 빠졌는지 안에서 알 수 없다.**

## 1. 묶음을 푼다

```bash
pnpm release:verify /media/반입/workfluence-2026-09-22
```

통과하면 매니페스트가 함께 출력된다. **버전과 git sha를 작업 기록에 적는다** — 나중에
"무엇이 들어갔나"를 답할 수 있는 유일한 단서다.

## 2. 이미지를 올린다

```bash
docker load -i images.tar
docker images | grep -E 'workfluence-app|postgres|nginx'
```

세 개가 다 보여야 한다. 하나라도 없으면 1절로 돌아간다.

## 3. 설정을 만든다

```bash
cp env.template .env
```

`.env`를 열어 값을 채운다. **비어 있는 키가 있으면 앱이 기동에서 실패하고 어느 키인지
말해 준다** — 그래서 빠뜨릴 수 없다. 반드시 채워야 하는 것:

| 키 | 무엇 |
|---|---|
| `WF_PG_PASSWORD` | 데이터베이스 비밀번호 (새로 만든다) |
| `WF_SESSION_SECRET` | 세션 서명 키. **32자 이상** |
| `WF_ROOT_PASSWORD` | 최초 관리자 비밀번호. 첫 로그인에서 바꾼다 |
| `WF_OIDC_*` | 사내 인증을 쓸 때만 |

TLS 인증서는 `certs/cert.pem`·`certs/key.pem`에 둔다. **묶음에 들어 있지 않다** —
인증서는 저장소에도 반입 묶음에도 넣지 않는다.

## 4. 데이터베이스를 먼저 띄운다

```bash
docker compose -f compose.yml --env-file .env up -d postgres
docker compose -f compose.yml ps
```

`healthy`가 될 때까지 기다린다.

## 5. 표를 만든다 — **사람이 따로 하는 단계다**

```bash
docker compose -f compose.yml --env-file .env run --rm api node dist/db/migrate.js
```

운영에서는 기동과 함께 자동으로 바뀌지 않는다. 두 번 실행해도 결과가 같다.

## 6. 전부 띄운다

```bash
docker compose -f compose.yml --env-file .env up -d
docker compose -f compose.yml ps
```

## 7. 사후 검증 — 여기까지 해야 끝이다

| 확인 | 명령·행동 | 기준 |
|---|---|---|
| 앱이 산다 | `curl -sk https://<호스트>/api/health` | `{"status":"ok","db":"ok"}` |
| 화면이 뜬다 | 브라우저로 접속 | 로그인 화면 |
| 로그인된다 | `root` / `.env`의 비밀번호 | 비밀번호 변경 화면으로 간다 |
| 문서를 만든다 | 공간 → 페이지 → 저장 | 버전이 2가 된다 |
| 파일이 붙는다 | 첨부 올리고 내려받기 | 원래 이름 그대로 |
| 기록이 남는다 | 관리자 → 감사로그 | 방금 한 일이 보인다 |
| 되살아난다 | `docker kill workfluence-api` 후 30초 | 다시 `healthy` |

마지막 줄은 **재부팅 후 자동 기동과 같은 경로**를 확인하는 것이다 (`restart: unless-stopped`).
재부팅을 할 수 있는 창이 있으면 실제로 한 번 하고 7절 전체를 다시 본다.

## 8. 첫 백업을 뜬다

반입 당일에 **비어 있는 상태의 백업**을 한 번 떠 둔다. 복원 절차가 이 환경에서 도는지를
사고가 나기 전에 확인하는 것이 목적이다.

```bash
pnpm backup:create
```

## 9. 잘 안 될 때

| 증상 | 먼저 볼 것 |
|---|---|
| `docker load`가 실패한다 | 디스크 여유. `df -h /` |
| 앱이 켜지다 죽는다 | `docker compose logs api --tail 50`. 대개 `.env`의 빈 키다 |
| 화면이 전부 404인데 `/api/health`는 200 | `운영가이드_장애대응.md` 3절 |
| 접속 자체가 안 된다 | 인증서 파일과 포트. `docker compose logs nginx` |
| 첨부가 안 올라간다 | `운영가이드_장애대응.md` 7.9절 |

그 밖의 증상은 [`docs/운영가이드_장애대응.md`](운영가이드_장애대응.md)를 본다.
