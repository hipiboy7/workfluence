## 1. 요구사항과 확인

| # | 확인 | 어디서 |
|---|---|---|
| FR-1600 | 관리자와 root가 member에게 셋을 주고 거둔다 — 이전·이후를 돌려주고 행에 남는다. 사용자 관리의 member 줄에 셋이 있고, 관리자가 켜면 목록 전체를 보낸다 | 통합(`apps/api/src/auth/auth.integration.spec.ts`) · 컴포넌트(`apps/web/src/pages/admin/AdminUsersPage.spec.tsx`) · E2E `e2e/grants.spec.ts` |
| FR-1601 | LLM 연결 관리는 root만 — 관리자는 주지도 거두지도 못한다(LLM 연결 관리를 가진 관리자도). 화면에서는 보이기만 한다 | A등급(`packages/shared/src/permissions.spec.ts` — `canGrant`) · 통합 · 컴포넌트 |
| FR-1602 | 받은 member는 다시 맡기지 못한다. 받는 역할이 아니면 400 — 관리자에게 셋, member에게 LLM 연결 관리, root에게 무엇이든 | A등급 · 통합 |
| FR-1603 | 역할이 바뀌면 받을 수 없는 위임이 사라진다 — member가 관리자가 되면 셋이, 관리자가 member가 되면 LLM 연결 관리가. 문장 하나로 역할만 바꾸면 DB가 받지 않는다 | 통합 · 제약 통합(`apps/api/src/db/constraints.integration.spec.ts`) |
| FR-1604 | 관리자는 셋을 받은 member를 관리한다(초기화·세션 종료). 자기에게 없는 위임(LLM 연결 관리)을 가진 관리자는 지금처럼 관리하지 못한다 | A등급(`canManageUser`) · 통합 |
| FR-1605 | 받거나 잃으면 다음 요청부터 먹는다 — 가드가 싣는 사용자 행에 바로 보이고, 화면은 새로 고치면 다시 쓰기가 생긴다 | 통합 · E2E |
| FR-1610 | 중지할 때 건 사람이 주인인지 적고 보기에 싣는다. 0012가 이미 중지된 공간을 **마이그레이션 파일의 문장 그대로** 채운다 — 만든 사람·Crew의 owner면 주인, editor·관리자·모름은 관리자가 건 것, 활성 공간은 건드리지 않는다 | 통합(`apps/api/src/spaces/spaces.integration.spec.ts`) · 제약 통합 |
| FR-1611 | 관리자가 건 중지는 `space.unsuspend`를 받은 **주인**만 푼다 — 받지 않은 주인은 403과 까닭, 다른 위임으로는 못 풀고, 권한이 있어도 주인이 아니면 못 푼다. 개인 공간도 같다. 관리자와 스페이스 관리 전체는 언제나 푼다 | A등급(`spaceAccess`) · 통합 · E2E |
| FR-1612 | 누가 중지했는지 보인다 — 관리 칸의 **주인이 중지한 스페이스다.** / **관리자가 중지한 스페이스다.**, 풀지 못하는 주인에게 까닭(다시 쓰기 단추 없음), 관리 콘솔 상태 칸의 **주인이 걸었다** / **관리자가 걸었다** | 컴포넌트(`apps/web/src/components/SpaceManage.spec.tsx`·`apps/web/src/pages/admin/AdminSpacesPage.spec.tsx`) · E2E |
| FR-1620 | 관리 칸에서 **새 분류** — 만든 것이 고른 상태가 되고 저장해야 붙는다. 같은 이름이면 있던 것을 고른다. 칸의 Enter는 만들기다 | 컴포넌트 · E2E |
| FR-1621 | 이름 바꾸기·지우기는 만든 사람과 관리자 — 남의 공간(휴지통 포함, Crew의 owner로 있는 공간은 자기 것)이 쓰면 관리자와 분류 관리를 받은 사람만. 거절의 까닭 둘. 관리 칸에는 내가 만들었고 바꿀 수 있는 것만 | A등급(`categoryAccess`) · 통합 · 컴포넌트 · E2E(서버의 403) |
| FR-1622 | 지우면 쓰던 공간(휴지통 포함)이 분류 없음이 되고, 감사 `category.delete`에 `cleared`(id·이름·휴지통 여부) | 통합 · E2E |
| FR-1623 | 분류 목록이 줄마다 `createdBy`·`access`·`usage { spaces, otherSpaces }`를 싣는다 — 사람마다 다르다 | 통합 · 컴포넌트 |
| FR-1624 | 지우기 전에 몇 개가 분류 없음이 되는지 묻는다(글자 그대로 견준다 — T-069) | 컴포넌트 · E2E(확인 창의 글) |
| FR-1630 | 스페이스 관리 전체 — Crew가 아닌 공간도 중지·다시 쓰기·중지된 것 지우기, 모든 스페이스 목록, 휴지통의 지운 스페이스 보기·되살리기. 다른 위임으로는 못 한다(404·403). 관리 콘솔·첫 화면 메뉴·휴지통이 그 위임으로 열린다 | 통합(스페이스·`apps/api/src/trash/trash.integration.spec.ts`) · 컴포넌트(`AdminSpacesPage`·`apps/web/src/pages/SpacesPage.spec.tsx`·`apps/web/src/pages/TrashPage.spec.tsx`) |
| FR-1631 | 받은 사람도 Crew가 아닌 공간의 내용은 읽지 못한다 — 읽기 경로는 404, 목록과 바꾼 뒤의 보기에 설명이 없다. 이름·설명·분류도 바꾸지 않는다(editor로 있는 공간도 — `canEditInfo`) | A등급 · 통합 |
| NFR-150 | 위임 판정은 한 곳(`DELEGATION`) — A등급 시험이 표의 칸마다 본다(`can`·`grantsForRole`·`canGrant`·`canManageUser`) | A등급 |
| NFR-151 | DB 제약이 목록·받는 역할과 같다 — 목록의 CHECK를 코드와 견주고, 행위 넷 × 역할 셋을 SQL로 넣어 본다 | 제약 통합 |
| (동시성) | 동시에 상태를 바꾸면 뒤의 것은 409(주인이 건 중지가 덮이지 않는다). 지워지는 분류를 붙이면 400(500이 아니다). 남이 붙이는 사이 만든 사람이 지우면 기다렸다가 다시 세어 403 — 세 시험 모두 앞의 일을 커밋 전에 붙잡아 두어 결정적이다 | 통합 |
| (같은 상태) | 같은 상태를 다시 보내면 쓰지 않는다 — 건 사람이 바뀌지 않고 감사 행이 없다. 권한을 받은 주인이 관리자가 건 중지를 제 것으로 바꿔 두지 못한다 | 통합 |
