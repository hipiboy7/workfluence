새 빌드(`pnpm build`)를 호스트 `:3100`에 띄우고 `pnpm test:e2e`(대상은 `E2E_BASE_URL`로 `:3100`) — **36 통과 · 실패 0 · 건너뜀 0 (2.4분).** 마지막 코드(`a542216`)의

- **관리자가 건 중지는 권한을 받은 주인만 푼다** — 주인이 팀 공간을 만들고, 관리자가 스페이스 관리에서 찾아 **중지**(확인 창) → 상태 칸 "중지 관리자가 걸었다" → 주인의 관리
  칸에 "관리자가 중지한 스페이스다."와 "주인도 다시 쓰기로 풀지 못한다", 다시 쓰기 단추 없음 → 관리자가 사용자 관리에서 그 사람을 찾아 **관리자가 건 중지 풀기**를 켠다
  (member 줄에 칸 셋, LLM 연결 관리 칸 없음 · PUT 200) → 주인이 새로 고치면 **다시 쓰기** → "다시 쓸 수 있게 했다." → 새 페이지 칸이 돌아온다.
- **분류는 누구나 만들고, 남이 쓰면 만든 사람은 못 지운다** — 만든 사람이 자기 개인 공간의 관리 칸에서 새 분류를 만들어 저장 → 분류 관리에 보인다 → 다른 사람이 자기 팀
  공간에 그 분류를 붙인다 → 만든 사람의 분류 관리에서 사라지고, 직접 부른 `DELETE`는 403 → 관리자가 스페이스 관리에서 "공간 2개 (만든 사람의 것이 아닌 공간 1개)"를 보고
  지운다 — 확인 창의 글이 "이 분류를 쓰는 공간 2개(휴지통 포함)가 \"분류 없음\"이 된다"를 담는다 → "쓰던 공간 2개는 분류 없음이 됐다." → 그 공간의 분류 칸이 "—", 관리 칸의
  분류가 비었다.
- 기존 흐름 여덟 파일 24곳이 페이지 **만들기**를 `exact: true`로 찾는다 — 관리 칸의 **분류 만들기**까지 잡았다(T-068). Phase 14의 스페이스 관리 흐름은 상태 칸의 "주인이
  걸었다"와 분류 지우기가 분류 없음이 되는 것으로 바꿨다.

병합 전에 넷을 돌렸다(모두 Opus 5.5) — 자체 점검 12 · 코드 리뷰 13 · 보안 검토 LOW 2 + 문턱 아래 7 · 문서 정합성 24. 오탐 0. 넷 다 높음이 없었다. 가장 값있던 것:

  코드 리뷰가 짚었다.
- **판정에 쓴 값을 쓰기의 조건에 다 넣지 않았다**(셋이 따로) — ABA로 권한 없는 주인이 관리자가 건 중지를 풀었고, 중지된 공간을 주인이 지웠다(T-070).
- **위임 칸이 목록 전체를 보내 옛 화면이 거둔 위임을 되살렸다**(보안 2 · 코드 리뷰 5).

## 9. 확인하지 못한 것

- **이미 중지된 공간의 채우기를 실제 데이터로** — 개발 DB·컨테이너 DB 모두 중지된 공간이 없었다(5절). 폐쇄망에 새 버전을 들일 때 반입 가이드 11절의 사후 검증에서
  `SELECT status, suspended_by_owner, count(*) FROM spaces WHERE status = 'suspended' GROUP BY 1, 2`로 본다.
- **넘겨받기와 경합의 409를 브라우저로** — E2E 두 흐름은 넘겨받기·409를 지나지 않는다. 컴포넌트 시험(단추·확인 창·보내는 본문·거절 뒤 다시 읽기)과 통합 시험(서버의 판정·
  경합)이 본다.
- **분류 쓰임의 비용** — 분류 목록은 부를 때마다 모든 분류의 쓰임을 질의 하나로 센다(`category_id`에 색인이 없어 공간 전체를 훑는다). 300명 규모(공간 수백 개)에서 재지
  않았다(보류 14에 더할 때).
- **Windows에서** — F-006의 러너(`.github/workflows/windows.yml`)를 Phase 15 코드로 돌리지 않았다. F-009(받아서 푸는 묶음)를 만들 때 같이 본다.
- 지우기와 **Crew가 늘어나는 것**이 겹치는 경합(설계서 D.6) — 시험하지 않았다. 휴지통으로 갈 뿐이다.
