# P7 설계서 — Hardening (반입 전 강화)

Phase 7은 **기능을 더하지 않는다.** Phase 6까지 만든 것 중 **반입하면 되돌리기 어려운 결함**만 닫는다.
근거는 CLAUDE.md 1.2절 보류 20과 `docs/internal/P6_검토서_SelfReview.md` §5(돌리지 못한 검토)다.

## C. 설계

### C.1 살아 있는 연결의 재판정 (FR-800)

업그레이드 때 한 번 판정하고 마는 것이 문제였다. 판정을 **연결이 사는 동안 되풀이**한다.

- `Member`에 `sid`(세션 id)와 `spaceId`를 들려 둔다. 업그레이드 때 이미 안 값이라 다시 구하지 않는다.
- 이미 1초마다 도는 `sweep()`에 재판정을 얹는다. **타이머를 새로 만들지 않는다** — 타이머가 둘이면 종료 순서가 둘이 된다.
- 주기는 `WF_COLLAB_RECHECK_MS`(기본 300000). 연결마다 마지막 판정 시각을 들고 그것이 지난 것만 본다.
- 판정에 실패하면 **1008(policy violation)로 닫는다.** 화면은 이미 `onclose`를 `offline`으로 보여 준다.
- 판정 중 오류가 나면 **끊지 않는다.** DB가 잠깐 흔들렸다고 편집을 끊으면 그쪽이 더 나쁘다. 다음 주기에 다시 본다.

세션 조회는 `expire > now()`만이 아니라 **절대 타임아웃까지** 본다 (FR-808). HTTP 가드는 `session.createdAt`으로 12시간을 강제하는데 게이트웨이가 `expire`만 보면 둘의 판정이 갈린다.

### C.1.1 즉시 통지 (FR-805)

주기만으로는 **사고 대응이 5분 늦는다.** 그렇다고 `UsersService`가 게이트웨이를 import하면 인증 모듈이 실시간 편집에 묶인다 (2절 DIP).

그래서 **둘 다 아무것도 import하지 않는 가운데 지점**을 둔다 — `apps/api/src/common/revocation.bus.ts`. 세션을 끊는 쪽이 `revoke(userId)`를 부르고, 게이트웨이가 구독한다. 버스는 둘 중 누구도 모른다.

```
UsersService ──revoke(userId)──▶ [RevocationBus] ──▶ CollabGateway (구독)
   (비밀번호 변경 · 관리자 강제 종료)                        그 사용자의 소켓을 닫는다
```

**주기 재판정을 없애지 않는다.** 즉시 통지는 "끊는 동작"이 있는 경우만 잡는다 — Crew에서 빠지는 것, 스페이스가 중지되는 것, 계정이 만료되는 것에는 부를 자리가 없다. 둘은 서로를 대신하지 못한다.

### C.2 하트비트 (FR-801)

- `WF_COLLAB_PING_MS`(기본 30000)마다 서버가 ping을 보낸다. 브라우저는 pong을 자동으로 돌려준다 — **화면 코드를 고치지 않는다.**
- pong을 받으면 `alive=true`. 다음 ping을 보낼 때 `alive`가 `false`면 그 연결을 `terminate()`한다.
- nginx `proxy_read_timeout 300s`보다 훨씬 짧아 프록시가 먼저 끊지 못한다.

### C.3 작성자 오염 (FR-802)

원인은 화면이 접속 직후 자기 문서 전체를 보내는 것(`CollabEditor.tsx`)과, 서버가 **`MSG_UPDATE`를 받았다는 사실만으로** `lastActor`를 바꾸는 것이다. 빈 문서라 내용은 하나도 안 바뀌는데 작성자만 바뀐다.

고치는 방법은 **Yjs에게 물어보는 것**이다. `Y.applyUpdate(doc, payload, member)`로 오리진을 실어 적용하고, 방을 만들 때 걸어 둔 `doc.on('update', (_, origin) => …)`에서 오리진이 멤버일 때만 `lastActor`·`lastChangeAt`을 고친다.

> **상태 벡터를 비교하는 방법은 쓰지 않는다.** 그쪽이 간단해 보여 먼저 재 봤는데, **순수 삭제가 상태 벡터를 바꾸지 않는다.** 그 방법을 썼으면 "지우기만 한 편집"이 저장되지 않는다. 실측은 `P7_검증기록_Hardening.md` §2에 있다.

### C.4 `taskList` 제거 (FR-803)

`packages/shared/src/document.ts`의 허용 목록과 `html.ts`의 태그 매핑에서 `taskList`·`taskItem`을 뺀다.

허용 목록을 좁히는 것은 **기존 문서를 거부할 수 있는 변경**이다. 그래서 먼저 셌다 — 개발 DB `page_versions` 25건·`page_templates` 0건에 `task`를 담은 문서는 **0건**이다. 편집기가 그 노드를 만들 수 없고 가져오기 기능도 없으므로 만들어질 경로 자체가 없다. 운영은 아직 반입 전이라 데이터가 없다.

### C.4.1 그 밖의 좁히기 (FR-806·807)

- **`Origin` 검사.** 이 앱의 CSRF 방어는 `SameSite=Lax` + 커스텀 헤더 두 겹인데 **WebSocket은 헤더를 붙일 수 없어 한 겹뿐**이다. 업그레이드 요청의 `Origin`을 `Host`와 대조하고 다르면 거부한다. `Origin`이 아예 없는 요청(브라우저가 아닌 것)은 거부한다 — 우리 화면은 늘 보낸다.
- **표시 이름의 CR·LF.** 지금은 메일을 JSON으로 보내 무해하다. 그러나 사내 메일 API가 제목을 SMTP 헤더로 옮기는 순간 헤더 인젝션이 된다(보류 18). **그 날 코드를 고칠 사람이 이 연결을 기억할 것이라고 기대하지 않는다.**

### C.5 이미지 줄이기 (FR-804)

런타임 이미지의 `node_modules`에 **의존성이 함께 들여온 소스맵 9.8MB와 문서 11.7MB**가 들어 있다. 실행에 쓰이지 않는다. 빌드 스테이지에서 지운다 — 런타임 스테이지에서 지우면 앞 레이어에 그대로 남아 크기가 안 준다.

`LICENSE`는 **지우지 않는다** (7절 라이선스 목록).
