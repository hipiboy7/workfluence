## 3. 시험이 잡은 것 (설계서 I절 5·6)

- 한 연결이 연달아 보낸 메시지의 번호가 뒤바뀔 수 있었다 — 프레임마다 저장을 바로 불렀다. 연결마다 처리 줄을 둬 고쳤다(시험 "순서").
- 화면이 방 목록을 `hello`를 받은 뒤에야 받아, 연결이 막히면 비어 보였다 — 컴포넌트 시험이 잡았다. 연결과 상관없이 먼저 받게 고쳤다.
- 편집 게이트웨이가 채팅 경로를 404로 닫을 뻔했다(설계 단계에서 먼저 발견 — 통합 시험으로 고정).

## 3-3. 검토 반영 뒤의 컨테이너·E2E 재확인 (2026-10-12, 커밋 `debfd40`)

- **이미지 재빌드** — `deploy/build.sh`, 종료 코드 0, `tiffanie-workfluence-app:latest` **382MB**(예산 400MB 이하). 제 스택(`tiffanie-workfluence`)에서 마이그레이션(`run --rm tools node dist/db/migrate.js` — 앱 계정 권한 적용) 뒤 `docker compose up -d`로 api를 다시 만들었다.
- **nginx 너머(`https://localhost:8444`) 스모크** — 일회용 계정 둘로: 로그인 201 → 토큰 발급 201 → 1:1 방 만들기 201(`created: true`) → **화면 입구(세션 쿠키+Origin)와 토큰 입구가 둘 다 `hello`** → 토큰 연결이 보낸 메시지가 화면 연결에 도착 → 보낸 연결이 `ack` → 모르는 WebSocket 경로 404 → **토큰 폐기 후 그 연결이 close 4401**. `/api/auth/config`가 `chatEnabled: true`를 준다. api 로그의 `level 50`(오류) 0줄. 일회용 계정은 지웠다.
- **개발 서버 E2E** — `pnpm test:e2e e2e/chat.spec.ts e2e/collab.spec.ts` **8건 통과**(1.1분): 채팅 2건(두 사람의 대화 — 안 읽은 수·새로 고침 없이 도착, 토큰으로 붙은 클라이언트가 받고 답하고 폐기로 끊김)과 실시간 편집 6건(두 게이트웨이가 한 서버에 붙은 회귀).

## 4. 확인하지 못한 것

- **세션 유휴 만료와 오래 열어 둔 채팅 화면** — 아무도 말하지 않는 방을 30분 넘게 열어 두면 세션이 만료되고 주기 재판정이 연결을 닫는다(close 4401). 실제로 오래 열어 두고 재현하지 않았다.
- **부하** — 방·메시지가 많을 때(방 목록의 마지막 메시지 조회, 연결 수백 개)는 재지 않았다.
- **실제 AI 에이전트와의 연동** — `aiagent` 쪽 구현으로 붙여 보지 않았다. E2E·스모크는 `ws` 패키지로 만든 클라이언트다(모의 통과는 완료가 아니다 — 9.1절과 같은 판단).
- **메시지의 보존·삭제·감사** — 하지 않았다(보류 39).
