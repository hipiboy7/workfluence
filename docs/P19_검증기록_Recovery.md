- `e2e/auth.spec.ts` — 비밀번호 찾기의 두 칸이 이름·email이다(초기화 요청 알림이 관리자의 알림 영역에).

병합 전에 넷을 돌렸다(모두 Opus 5.5) — 자체 점검 13 · 코드 리뷰 11 + 추가 보고 15 · 보안 검토 문턱 이상 0(문턱 아래 3) · 문서 정합성 30. 오탐 0. 반영분만 다시 본 좁은 자체
점검 9. 가장 값있던 것:

- **폼 안의 폼**(자체 1 · 코드 1) — 댓글 칸의 링크 대화가 댓글 폼 안에 들어, Chromium에서는 페이지가 다시 불려 쓰던 댓글이 사라지고 React로는 링크 없는 댓글이 등록됐다.
- **되돌리기가 저장 충돌 방어를 지나쳤다**(코드 2) — 바깥 값을 따라간 변경이 되돌리기 이력에 들어갔다.
- **셋이 따로 찾은 세션 틈**(보안 1) — 재설정 해시가 로그인 줄 밖이라 앞선 로그인의 세션 행이 되살아날 수 있었다(P13 D.4가 예고한 조건). 구조적 방법은 보류 37.
- **반영이 반대쪽 틈을 열었다**(코드 4 → 추가 4) — 보내기 실패 뒤 간격을 풀면 받아 놓고 실패를 알리는 API로 메일함을 채운다. 값과 간격을 모두 둔다.

## 10. 확인하지 못한 것

- **실제 사내 메일 API로 재설정 메일 한 통** — 개발 서버에서 닿지 않는다(보류 18 — 현장, 반입 가이드 10-1절 ⑥). 그 API가 받아 놓고 늦게 답하는지, 링크를 어떻게 그리는지(평문의
  긴 주소를 줄 바꿈으로 자르는지)는 현장에서 본다.
- **메일함이 곧 계정이라는 판단의 사내 보안 검토** — 받지 않으면 운영 설정으로 끈다(A.1-2). 설계 판단이라 시험으로 닫을 수 없다.
- **여러 사람이 동시에 링크를 쓰는 부하** — 링크 쓰기는 계정마다 줄을 선다. 몰려서 오는 경우(교육 뒤 한꺼번에 재설정)는 재지 않았다(보류 31과 같은 자리).
- **실시간 편집을 끈 서버에서 409 뒤의 헛 되돌리기 단추** — 불러온 뒤 앞의 이력이 남아 단추가 켜져 있고 눌러도 아무 일이 없다(좁은 재점검 N9 — 그대로).
- **실제 브라우저의 CSS 폭**(`width: auto`의 문단 형식 칸)은 E2E의 줄 높이로만 봤다 — Firefox·Edge에서는 보지 않았다.
- **Windows 사용자의 눈** — 새 화면(서식 단추 줄, 비밀번호 찾기 카드)은 러너가 띄워 봤을 뿐, 사람이 Windows에서 써 보지 않았다(사용자에게 안내했다).
