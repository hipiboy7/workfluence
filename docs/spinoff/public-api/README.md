# 스핀오프 — 공개 API (Public API v1)

- 무엇: workfluence의 기능을 **LLM 에이전트와 2차 개발자**가 프로그램으로 쓰도록 여는 REST API(`/api/v1`)와 그 인증(JWT)
- 작업 브랜치: `tanminkwan-rest-api` (main에서 분기, PR로 돌려보낸다)
- 기능 요청 원문: [`요청원문.md`](요청원문.md) · 백로그 항목: [`docs/기능백로그.md`](../../기능백로그.md) F-015
- 작성일: 2026-10-02

## 왜 따로 두는가

본 저장소의 문서는 Phase 번호로 줄을 선다([`CLAUDE.md`](../../../CLAUDE.md) 10절). 이 일은 원 개발 흐름(Phase 0~20)과 **다른 기여자가 다른 브랜치에서** 하는 갈래(스핀오프)라, 사용자 지시("docs에 의미있게 스핀오프 directory 만들고")로 문서를 이 디렉토리 한 곳에 모은다. 본 문서들(설계서_Architecture·가이드)에는 병합 시점에 **이 디렉토리를 가리키는 한 줄**만 더한다 — 같은 사실을 두 곳에 쓰지 않는다(1.3절).

> **규칙과 다른 점 하나.** `CLAUDE.md` 11절은 "Claude가 쓴 작업 계획은 파일로 남기지 않는다"이다. 이 디렉토리의 계획서는 **사용자가 명시적으로 요청해서** 둔다. 설계서가 나오면 계획서는 설계서를 가리키고 겹치는 내용을 지운다.
