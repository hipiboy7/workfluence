## 2. 가장 값있던 것

### ① 옮기기 한 번이 형제 수만큼 쓰고, 기다리는 요청이 연결을 쥔다 (보안 1 · 코드 리뷰 4)

첫 판은 옮길 때마다 새 부모 아래 형제의 자리를 0부터 다시 매겼다. 자리가 색인에 들어 있어 줄마다 본문의 검색 색인까지 다시 쓴다 — 시험 DB에서
본문 50KB 형제 300개 아래로 맨 앞에 옮기는 데 **1.29초**(한 줄씩)였고, 한 문장으로 모아도 **1.23초**였다(형제 1,000개·본문 2KB는 0.50초 → 0.23초).
문장 수가 아니라 쓰는 줄 수가 비용이다. 그래서 자리 값에 **틈**(1024)을 두어 보통은 옮긴 한 줄만 쓰고, 틈이 없을 때만 한 번에 다시 매긴다(`placeAt`,
A등급). 잠금을 기다리는 요청이 상한 없이 연결을 쥐는 것은 `lock_timeout` 2초 → 409로 막았다(T-026과 같은 자리).

### ② 트리 잠금이 옮기기끼리만 줄을 세웠다 (코드 리뷰 6 · 자체 점검 10 · 코드 리뷰 7)

옮기기만 잠그면 옆의 일과 엇갈린다 — 깊이 9 아래로 옮기는 사이 그 아래에 만들면 깊이 11, 지우는 부모 아래로 옮기면 고아, 동시에 만들면 자리 겹침.
네 길(옮기기·만들기·지우기·휴지통 되살리기)이 같은 잠금을 쓴다(`tree-lock.ts`). 되살리기는 여기에 더해 **깊이를 보지 않았다** — 자식을 지운 채
부모를 깊이 10으로 옮긴 뒤 자식을 되살리면 11단계였다. Phase 3·4부터 있던 길인데 옮기기 화면이 생겨 화면만으로 닿게 됐다. 이제 맨 위로 되살린다.
길마다 불변식을 따로 지키던 구조는 T-064에 적었다.

### ③ 운영자의 셸과 DB 슈퍼유저에 사용자가 지은 글자를 넣게 했다 (보안 2)

장애대응 7.36절의 새 명령이 `WHERE c.name = '<분류 이름>'`에 분류 이름을 붙여 넣게 했다. 분류는 member도 만들 수 있고 이름은 아무 글자다 — 따옴표로
SQL을, `$(…)`로 셸을 바꿀 수 있다. 입력 없이 "쓰이는 분류 전부"를 보이는 질의로 바꿨다. 기존 명령의 자리 채움값은 모양이 정해진 것(UUID·아이디)
뿐이었고 자유 글자를 받는 것은 이 줄이 처음이었다.

### ④ 다시 읽을 때마다 사람이 고른 값이 되돌아갔다 (코드 리뷰 5 · 자체 점검 2)

## 4. 돌연변이 — 반영분

- **서버 열넷** — 모두 잡았다: 만들기·지우기·옮기기가 잠그지 않기, 다시 매기기 문장 빼기, 형제 질의의 스페이스 조건·지움 조건 빼기, 다른 스페이스를
  400으로(옛 코드), 감사에 요청값만(옛 코드), 모든 스페이스를 SQL에서 자르지 않기, 모든 스페이스의 권한 검사 빼기, 만들기의 간격 빼기(옛 +1),
  되살리기의 깊이 판정 빼기, 깊이 판정을 한 칸 어긋나게(`>=`), 잠금을 부모 판정 뒤로.
- **화면 열다섯** — 모두 잡았다(`docs/P14_검증기록_Spaces.md` 3절).
- **반영분 점검 뒤 서버 열셋** — 모두 잡았다: 옮기기·지우기·되살리기가 잠근 뒤 다시 읽지 않기, 만들기가 맨 뒤를 읽은 뒤 잠그기, 지우기가 자식을 센
  뒤 잠그기, 만들기·옮기기가 잠그기 전에 권한을 보지 않기, `UuidPipe`와 방 이름이 소문자로 맞추지 않기, 트리 잠금이 트랜잭션을 보지 않기, 잠근 뒤
  한도를 0으로(옛 코드), 보기를 줄마다(옛 코드), 분류를 먼저 찾고 넣기(옛 코드 — 처음 시험은 경합이 생기지 않아 **빠져나갔다**. 앞의 넣기를
  커밋 전에 붙잡아 두는 시험으로 바꾼 뒤 잡았다).
- **반영분 점검 뒤 화면 셋** — 모두 잡았다: 안쪽 목록의 기본 들여쓰기 남기기, 목록 실패를 화면 오류와 하나로, 만들기를 두 번 막지 않기.

## 6. 반영분의 좁은 자체 점검

1~5절의 반영(`60ce068` 뒤의 커밋과 문서)만 다시 봤다 — `self-reviewer`, Opus 5.5. "고친 직후가 가장 위험하다"(`docs/internal/설계서_Agents.md`)대로
**반영이 새로 만든 결함**이 먼저 나왔다: 잠금을 옮기기·만들기·지우기·되살리기에 넓히면서 잠그기 전에 읽은 행을 그대로 썼고(N1), 트리를 목록 안의
목록으로 바꾸면서 들여쓰기가 세 배 반이 됐고(N3), 보류 32를 쓰면서 이미 있는 열을 "마이그레이션이 필요하다"고 적었다(N4).
