## 2. 가장 값있던 것

### ① 알림 영역이 세션의 유휴 만료를 없앴다 (높음 — 셋이 따로)

F-010 8번이 모든 화면에 알림 영역을 두고 안 읽은 수를 30초마다 묻게 했다. 그 요청은 세션을 지나며 만료를 밀었다 — express-session의 `rolling`과 응답
끝의 `touch`가 저장소의 `expire`를 요청마다 지금 + 30분으로 올려, 열어 둔 탭은 절대 만료(12시간)까지 살았다. Phase 7은 일부러 "열어만 둔 탭은 이어 주지
않는다"로 설계했다(실시간 편집은 문서를 바꾼 사람만 연장한다) — 새 폴링이 그것을 모든 화면에서 우회했다. `rolling`만 끄면 모자란다(`touch`가 남는다) —
배경 표시(`x-wf-background`)가 붙은 요청은 `rolling`을 끄고 저장소의 `touch`를 비운 세션 미들웨어가 받는다(`apps/api/src/auth/session-middleware.ts`).
통합 시험이 `sessions.expire`와 `Set-Cookie`를 본다. 같은 요청이 앱·nginx 접근 로그를 30초마다 채우던 것(코드 14)도 함께 뺐다(5xx는 남긴다).

### ② 설계가 귀속 기록을 "자동 저장"으로 불렀다 (중간 — 보안 22)

감사 기록 단계 2가 `page.collab.save`·`flush`·`title` 셋을 뺐다. 뒤의 둘은 Phase 7·9의 보안 검토가 **누가 했는지 남기려고** 넣은 기록이다(사람이 누른
**저장하고 보기로**, 제목 바꾸기). 설계서 I절이 셋을 "실시간 편집의 자동 저장"으로 묶은 것이 틀렸다. 2는 `page.collab.save`만 뺀다 — A등급 Red를 먼저 썼다.

### ③ 화면이 옛 페이지를 들고 새 페이지를 지웠다 (중간 — 코드 15)

화면 전면이 페이지 트리를 왼쪽 칸에 두면서 페이지 보기끼리 옮겨 다니는 일이 흔해졌다. 트리로 옮기면 화면이 그대로 남아 주소만 바뀌고, 응답이 오기 전까지
앞 페이지의 제목·조치가 보였다 — 그 사이 **삭제**를 누르면 옛 제목을 보인 채 주소의 새 페이지를 지웠다. 댓글 초안도 따라갔다. 보기는 읽은 페이지만 그리고
본문을 페이지마다 새로 만든다. 편집·이력은 화면을 새로 만든다(설계서 J.12-14).
