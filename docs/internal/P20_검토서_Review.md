## 2. 가장 값있던 것

### ① 서명 확인이 서명 없는 RPM을 통과시켰다 (보안 S1 · 자체 3 — T-097)

가이드는 "`SIGNATURES NOT OK`·`NOKEY`가 있으면 설치하지 않는다"였다. 서명이 없는 RPM은 `rpm -K`가 `digests OK`만 내고 **종료 코드 0**이다 — 찾으라던 글자가 없다.
`NOKEY`는 `-v` 없이는 나오지도 않는다. 그리고 dnf는 파일로 까는 RPM의 서명을 보지 않아(`localpkg_gpgcheck` 기본 끔) 그대로 깐다. 보안 검토는 RPM 사본에서 서명을 떼어
봤고, 메인은 UBI 9.6에서 서명 없는 RPM을 `rpmbuild`로 만들어 옛 판정이 지나치고 dnf 기본이 `Complete!`로 까는 것까지 다시 봤다. 키 파일도 **첫 키의 지문만** 봐서
키를 하나 더 붙이면 지나갔다(`rpm --import`는 전부 들인다).

고친 것 — 판정을 **"좋은 모양을 확인한다"**로 뒤집었다. 현장은 `grep -v ': digests signatures OK$'`가 아무것도 내지 않아야 하고, 키는 `awk`가 `1:<지문>`(키 하나)을
내야 한다. 만드는 쪽은 공유 `rpmSignatureProblems`·`dockerKeyProblem`(A등급). 판정은 **임시 RPM DB**에서 먼저 하고(S2 — 처음 판은 지문을 보기 전에 키를 시스템
DB에 들였다), 통과한 뒤에 키를 들여 **`dnf install --setopt=localpkg_gpgcheck=1`** — 같은 서명 없는 RPM을 dnf가 `is not signed` · `GPG check FAILED`로 거절했다.

### ② `deps/`를 거꾸로 골랐다 (자체 1 · 보안 C5 — T-098)

처음 판은 빈 RHEL 9 대신 UBI 9.6으로 설치 거래를 세어 `iptables-libs`·`libnetfilter_conntrack`·`libnfnetlink`를 넣고 `nftables`를 "늘 있는 것"이라 적었다. 자체 점검이
이 서버의 RPM DB 사본에서 **Docker 거래를 되돌려**(`rpm -e --justdb`) 묶음을 넣어 보니 `nftables`·`libnftnl.so.11`이 모자랐다 — 이 서버(firewalld가 없다)에 docker-ce와
같은 거래로 들어온 것이 `nftables`·`libnftnl`·`iptables-nft`·`container-selinux`였다. 표준 설치(@core의 firewalld)에는 넷이 다 있어, 처음 판의 `deps/`는 **어느 서버에서도
쓸모가 없었다.** 보안 검토는 `iptables-nft`가 같은 판의 `iptables-libs`를 요구해 다른 부 버전에서 조용히 올리거나 부딪힌다는 것을 봤다. 고친 것 — `deps/` =
`iptables-nft`·`nftables`·`libnftnl`·`jansson`, 같은 부 버전일 때만(`PACKAGES.txt`의 첫 줄과 견준다), 고른 법을 설계서 A.1-5에.

### ③ firewalld는 Docker가 연 포트를 거르지 않는다 (보안 C1 · 자체 2)

처음 판은 "firewalld가 켜져 있으면 8443을 연다"였고, 7.41은 "다른 PC에서 안 되면 firewalld가 막는다"였다. RHEL 9의 firewalld(1.3.4)는 주소를 바꾼(DNAT) 연결을
영역 판정 전에 받아들이고(자체 점검 — 소스), Docker(29.6.1)는 firewalld에 제 영역과 전달 정책을 만든다(보안 검토 — 바이너리의 문자열). 여는 명령은 아무것도 바꾸지 않고,
그 진단은 진짜 원인(사이의 망·**망 대역 겹침** — C2)을 가렸으며, "firewalld가 노출을 정한다"는 거짓 안심을 줬다 — 누가 compose에 `ports:`를 더하면 막아 주지 않는다.
고친 것 — 0.4절(바꿀 것이 없다·밖으로 열리는 것은 접속 포트 하나), 7.41의 확인 순서(`ss -ltn` → 망 대역 → 사이의 망), 운영이관 6절(compose에 `ports:`를 더하지 않는다),
규칙서·범위 정의의 인수 기준 문구. firewalld가 켜진 서버에서 실측하지는 못했다 → 보류 38.

### ④ 빌드 쪽 셸 명령은 실패해도 멈추지 않았다 (자체 8)

`rpm -q`는 없는 패키지를 `package X is not installed`로 **표준 출력에** 내고, 그것이 `dnf download`의 인자가 됐다. 파일이 빠지면 `sha256sum`이 부분 목록을 쓰고 tar가 그대로
쌌다 — 현장의 `sha256sum -c`는 그것을 `OK`라고 한다. 셸 한 덩어리로 막으려다 보니 `!`는 `set -e`를 끄고 파이프의 종료 코드는 판정을 뒤집었다. 그래서 반입 묶음처럼
**스크립트로** 만들었다(`pnpm release:docker` — `CLAUDE.md` 4.1절의 `pnpm <script>`와도 맞다). 판정은 A등급 함수, 스크립트는 받고 쓰기만 한다.

### ⑤ 라이선스 — 사용자에게 물었다 (문서 5 · 자체 4)

Docker의 넷은 Apache-2.0이지만 Red Hat의 부품은 GPL 계열이다(`container-selinux` GPLv2, `iptables-nft` "GPLv2 and Artistic 2.0 and ISC", `nftables` GPLv2, `libnftnl` GPLv2+ —
`jansson`은 MIT). `CLAUDE.md` 7절은 GPL을 승인 없이 금지하고, Windows 체험 묶음의 LGPL도 승인을 받았다. 두 선택지(싣는다 / Docker 넷만 싣고 RHEL 부품은 현장의 매체에서)를
드렸고 **"승인 — 싣는다 (추천)"**을 받았다. 판·라이선스 목록은 묶음의 `PACKAGES.txt`, 판정은 리눅스빌드 가이드 12-1절과 `CLAUDE.md` 7절.
