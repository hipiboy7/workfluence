# P1_검토서_SelfReview — Phase 1 자체 점검

- 용도: Phase 1 종료 전 독립 검토 결과와 **각 지적을 어떻게 처리했는지** 남긴다
- 규칙: [`CLAUDE.md`](../../CLAUDE.md) 1.1절 5단계. Phase 1은 `/security-review`가 **필수**다
- 실행일: 2026-09-21 / 작성 LLM: Claude Opus 5

| 점검 | 도구 | 결과 |
|---|---|---|

## 1. 보안 점검 — 전부 반영

| # | 심각도 | 지적 | 처리 |
|---|---|---|---|
| S1 | **높음** | `POST /api/auth/recover-password`(공개)가 아이디+email 일치만으로 피해자 비밀번호를 덮어쓰고 **평문을 응답으로** 돌려줬다. 잠금까지 풀렸다. 대상이 admin이면 권한 상승 | **기능을 없앴다.** 요청만 감사로그에 남기고 관리자 초기화로 보낸다 (FR-209a, 설계서 2.4절) |
| S2 | 보통 | 비밀번호를 바꿔도 **다른 기기의 세션이 살아 있었다.** `regenerate()`는 현재 세션 하나만 바꾼다 | 변경·초기화 시 `sess->>'userId'`로 전 세션 삭제 (FR-224) |
| S3 | 보통 | 가입 중복 오류가 아이디/email 중 어느 쪽인지 알려 줘 존재 확인 오라클이 됐다 | 단일 문구로 통일 |
| S4 | 보통 | 계정 복구가 IdP 전용 계정에 비밀번호를 부여해 **FR-217을 우회**시켰다 | 관리자 초기화도 `oidc_sub`가 있으면 거부 (FR-209b) |

**왜 S1이 생겼나.** 설계에서 **관리자 초기화(인증된 행위)와 본인 찾기(미인증)를 FR-209 하나로
묶었다.** 앞쪽은 타당하고 뒤쪽은 그렇지 않은데 같은 규칙을 줬다. 요구사항을 쓸 때 **누가
그 행위를 하는가**를 항목마다 적었다면 갈렸을 것이다.

## 2. 자체 점검 17건 — 처리 내역

### 2.1 고친 것 (9건)

| # | 심각도 | 지적 | 처리 |

## 3. 재현하지 못한 것

`pnpm check`에서 통합 테스트 3~4건이 **한 번** 깨졌다(`alice already exists`). 단독·반복
실행에서는 재현되지 않았고(6회 전부 통과) 두 점검이 각각 같은 증상을 봤다. 공유 테스트 DB에
동시 실행이 겹친 것으로 의심하나 **확정하지 못했다.**

원인을 모르는 채로 두면 나중에 진짜 회귀를 이 증상으로 착각한다. 그래서 `resetTables`가
정리 후 **users가 비었는지 확인하고 아니면 던지도록** 했다. 다음에 나면 "정리 실패"로 바로
드러난다.

## 4. 이 점검에서 배운 것

**"테스트가 있다"와 "검증된다"는 다르다.** #2는 통과하는 테스트였고 그래서 더 위험했다.
FR-236을 지키고 있다고 믿게 만들었기 때문이다. 테스트를 쓸 때 **그 테스트가 실패할 수 있는
조건**을 같이 생각한다. 실패할 수 없는 테스트는 항진 명제다.

**요구사항 한 줄에 행위자가 둘이면 쪼갠다.** S1의 뿌리는 FR-209가 관리자와 본인을 함께
가리킨 것이다.

**제외에는 대가가 따른다.** 커버리지에서 컨트롤러를 빼면서 "E2E가 본다"고 적었지만 그 E2E를
같은 커밋에서 쓰지 않았다(#6). 제외를 적는 순간 그 대가도 같은 커밋에서 치러야 한다.
