## 3. 확인 못 한 것

- A등급 "테스트 먼저": `tree.spec.ts`와 `tree.ts`가 같은 커밋이라 이력으로 선후를 증명할 수 없다.
  Phase 1에서도 같았다. **커밋을 나누면 검사가 실패한 상태로 올라가므로**(12.2절) 지금 방식을
  유지하되, 이 한계를 적어 둔다.

## 4. 이 점검에서 배운 것

**관문이 깨진 것을 못 알아챘다.** `pnpm check:env`는 1.1절 0단계인데, Phase 2 내내 실행하지
않아 `NOT READY`인 줄 몰랐다. `pnpm check`만 돌렸고 그것은 통과했다. **관문이 여럿이면 하나만
돌리는 습관이 생긴다.**

**"기능이 있다"와 "그 기능이 실행된 적 있다"는 다르다.** 이동 API는 있었고 거부 경로 테스트도
있었지만 **성공 경로는 한 번도 돌지 않았다.** 그런데 검증기록은 인수 기준 충족이라 적었다.
거부만 테스트하면 "막는 것"은 확인되지만 "되는 것"은 확인되지 않는다.

**같은 규칙을 세 곳에 두면 한 곳만 고치게 된다.** `.env` 파서가 그랬다. 1.3절이 문서에 대해
하는 말은 코드에도 그대로 적용된다.
