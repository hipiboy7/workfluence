- **이 문서는 내부 기록이다.** 산출물(`docs/`)에는 우리 판단의 근거만 쓴다 (`CLAUDE.md` 1.3절)

## 1. 이 대조의 범위

Phase 0은 **사용자에게 보이는 기능이 없다.** 기능 대조는 Phase 1부터 의미가 있다. 그래서 여기서는 Confluence가 **기반 수준에서 어떤 선택을 했는지**와 우리 선택을 견준다. 목적은 "따라 하기"가 아니라 **우리가 다른 선택을 했다면 그 대가를 알고 있는가**를 확인하는 것이다.

## 2. 대조

| 항목 | Confluence (Data Center 기준) | workfluence Phase 0 | 판정 | 이유 |
|---|---|---|---|---|
| 런타임 | JVM (Java), 자체 설치 프로그램 | Node.js 단일 프로세스, 컨테이너 | **변형** | 반입 묶음을 이미지 tar로 단순화한다. JVM 튜닝·설치 마법사가 폐쇄망 반입 절차를 늘린다 |
| 데이터베이스 | PostgreSQL·Oracle·MySQL·SQL Server 지원 | PostgreSQL 고정 | **제외(단순화)** | 여러 DB를 지원하면 SQL·인덱스·전문검색이 최소공배수로 수렴한다. 우리는 JSONB·trigram 같은 PG 기능을 쓴다 |
| 스키마 관리 | 기동 시 자동 업그레이드 | 마이그레이션 SQL 커밋 + **명시적 실행** | **변형** | 폐쇄망에서 기동과 함께 스키마가 바뀌면 되돌릴 방법이 없다. 배포 절차의 단계로 분리해 사전 검토·백업을 끼워 넣는다 |
| 설정 | `confluence.cfg.xml` + 관리 화면 + 시스템 속성 | `.env`(환경) / 상수(설계 고정) / DB `settings`(운영 조절) **3분류** | **변형** | 설정이 여러 곳에 흩어지면 "어디를 고쳐야 하는지" 판단이 매번 필요하다. 성격으로 위치를 정해 규칙화했다 |
| 미지의 설정 키 | 무시 | **기동 실패** | **변형** | 오타·미배선 키가 조용히 아무 일도 하지 않는 것이 폐쇄망에서 가장 비싼 실패다 |
| 헬스체크 | `/status` (앱 상태 위주) | `/api/health` — **DB 질의까지 수행** | **채택+강화** | 앱만 살아 있고 DB를 못 쓰는 상태를 정상으로 보고하면 컨테이너 재시작이 동작하지 않는다 |
| 로그 | 파일 기반(log4j), 회전 정책 설정 | **stdout JSON 한 줄** | **변형** | 컨테이너 표준. 수집기가 가져가고, 앱은 파일 회전·권한을 신경 쓰지 않는다 |
| 감사로그 | 앱 기능으로 제공, DB에 저장 | 앱 기능 + **DB 권한·트리거로 수정 차단** | **채택+강화** | 금융 감사에서는 "앱을 통하지 않은 변경"도 막아야 증적이 된다 |
| 플러그인 | 마켓플레이스·런타임 설치 | **없음** | **제외** | 폐쇄망에서 런타임 코드 설치는 반입 통제를 우회하는 경로가 된다. 필요한 기능은 본체에 만든다 |
| 프론트엔드 | 서버 렌더 + 부분 SPA | SPA를 api가 함께 서빙 | **변형** | 배포물을 한 프로세스로 줄여 반입·기동·헬스체크를 단순화한다 |
| 클러스터링 | Data Center에서 다중 노드 | 단일 노드로 시작, 세션은 DB | **제외(연기)** | 300명 규모에 동기화 비용을 먼저 지불할 이유가 없다. 세션만 미리 DB에 두어 확장 경로를 막지 않았다 |
| 전문 검색 | Lucene 색인(별도 디렉토리·재색인 도구) | PostgreSQL 내장(Phase 3) | **변형(보류)** | 반입 표면을 늘리지 않는다. 한글 2글자 질의 실측 후 판단 (`CLAUDE.md` 보류 2) |

## 3. 우리가 더 엄격하게 한 것

| 항목 | 이유 |
|---|---|
| 미지의 환경변수에서 기동 실패 | 조용한 실패가 가장 비싸다 |
| 마이그레이션 자동 적용 금지(운영) | 되돌릴 수 없는 변경을 기동에 끼우지 않는다 |
| 런타임 외부 자원 참조 0건을 CI에서 검사 | 폐쇄망에서 깨지는 자산을 반입 전에 잡는다 |
| 의존성 라이선스·시크릿 검사를 CI 관문으로 | 공개 저장소 + 반입 심사 |

## 4. 우리가 포기한 것 (알고 있는 대가)

| 포기한 것 | 대가 | 감수하는 이유 |
|---|---|---|
| 다중 DB 지원 | 고객사 표준 DB가 다르면 이식 비용 | 자체 운영 시스템이라 DB는 우리가 정한다 |
| 플러그인 생태계 | 기능 확장을 직접 만들어야 한다 | 폐쇄망에서 외부 코드 반입은 어차피 통제 대상 |
| 성숙한 전문 검색 | 한글 검색 품질·성능을 직접 검증해야 한다 | Phase 3에서 실측하고 미달이면 대안을 반입한다 |
| 다중 노드 | 단일 장애점 | Phase 5 부하 실측 후 판단. 세션은 이미 공유 가능 |

## 5. Phase 1 대조 예고

Phase 1에서는 **계정·권한 모델**을 대조한다: 사용자 상태(활성·비활성·잠김), 그룹과 권한의 관계, SSO 연동 방식, 감사 이벤트 목록. 그때 이 문서와 같은 형식으로 `P1_검토서_ReferenceComparison.md`를 쓴다.
