# P17 설계서 — Ui (Windows 체험에서 나온 개선 — F-010)

Phase 17은 사용자가 Windows 묶음(F-009)을 써 보고 적은 개선 열 가지(`docs/기능백로그.md` F-010)를 한다. 조각으로 나눠 끝낸 것부터 적는다 —
비밀번호 변경 화면(1·9번), 편집기와 댓글의 쓰는 칸(4·5번), 시스템 관리자 아이디 찾기 안내(7번), 비밀번호 초기화 요청 알림과 모든 화면의 알림 영역(8번).
감사 기록 단계(10번)는 I절, 화면 전면(2·3·6번)은 J절이다.

- 요청 원문: `docs/prompts/phase17/scope.md`
- 요구사항 번호: **FR-1800**, 비기능 **NFR-170**부터
- 선행: [`docs/P4_설계서_Admin.md`](P4_설계서_Admin.md) C절(알림함) · [`docs/P1_설계서_Auth.md`](P1_설계서_Auth.md) FR-208·209a(계정 찾기 — 같은 모양의 응답) ·
  [`docs/P11_설계서_Ops.md`](P11_설계서_Ops.md) D.1(관리의 우열 — 위임까지 본다) · [`docs/P13_설계서_Readiness.md`](P13_설계서_Readiness.md)(비밀번호 변경·정지)
- 구조: [`docs/설계서_Architecture.md`](설계서_Architecture.md)

## A.1 묻지 않고 정한 것 — 근거와 되돌릴 조건 (8번)

| # | 정한 것 | 근거 | 되돌릴 조건 |
|---|---|---|---|
| 1 | 초기화 요청은 그 사람을 **관리할 수 있는** 활성 관리자·시스템 관리자에게만 간다 — `canManageUser` 한 곳 | 알림을 받고도 초기화 단추가 막히면 쓸모가 없다. 관리의 우열(위임까지 — P11 보안 검토 1)을 다시 구현하면 사용자 관리 화면과 어긋난다 | — |
| 2 | 알림은 **넣은 아이디와 email이 활성 계정과 맞을 때만** 만든다. 응답은 그대로 같다(FR-208·209a) | 맞지 않은 요청까지 알리면 누구나 관리자의 알림함을 채울 수 있다. 맞지 않은 요청은 감사로그(`auth.password.recover`, `found: false`)에 있다 | — |
| 3 | 응답은 알림을 **기다리지 않는다**(NFR-170) | 맞을 때만 쓰기가 하나 더 붙는다 — 기다리면 걸린 시간이 "그런 계정이 있다"를 말한다 | — |
| 4 | 읽지 않은 같은 요청이 있으면 또 만들지 않는다(FR-1802). 확인과 쓰기 사이를 잠그지 않는다 | 로그인하지 않은 경로라 되풀이할 수 있다(IP별 제한이 있어도 쌓인다). 동시에 둘이 오면 같은 알림이 두 개 생길 수 있다 — 해가 없어 잠그지 않는다 | 같은 알림이 겹쳐 보인다는 보고가 오면 부분 유일 색인을 둔다(마이그레이션) |
| 5 | 누가 초기화하면 그 사람의 요청 알림은 받은 사람 **모두에게서** 읽음이 된다(FR-1803) | 둘이 같은 요청을 받아 둘 다 초기화하면 먼저 전한 임시 비밀번호가 쓸모없어진다 | — |
| 6 | 관리자에서 내려가면 초기화 요청 알림은 목록에도 안 읽은 수에도 없다(FR-1804) — 지우지 않는다 | 누가 초기화를 요청했는지는 관리자의 일이다. 다시 올라가면 그대로 보인다 | — |
| 7 | 알림 영역은 **화면 맨 위 오른쪽의 한 줄**이다 — 화면 위에 떠 있지 않는다(펼친 목록만 뜬다). 스페이스 목록 머리말의 **알림 (N)** 링크는 뺐다 | 떠 있으면 각 화면 오른쪽 위의 단추를 가린다. 같은 수를 두 곳에 두면 한쪽이 늦게 센다 | **옮겼다** — 한 틀의 위 막대 오른쪽(J.3.2) |
| 8 | 안 읽은 수는 **화면을 옮길 때와 30초마다** 다시 묻는다(`NOTIFICATION_POLL_MS`). 서버가 밀어 주지 않는다. **그 물음은 배경 요청이다**(`BACKGROUND_HEADER`) — 세션을 늘리지 않고 접근 로그(앱·nginx)에 남기지 않으며, 가려진 탭은 묻지 않는다. 로그에서 빼는 것은 그 경로(`BACKGROUND_POLL_PATH`)의 GET뿐이다 — 표시는 누구나 붙이므로, 처음 판처럼 경로를 보지 않으면 표시 하나로 모든 요청이 로그에서 사라진다(좁은 재점검). 세션을 늘리지 않는 것은 어느 경로든 같다(자기 세션만 짧아진다)(병합 전 검토 — 처음 판은 여느 요청이라 열어 둔 탭의 유휴 만료가 오지 않았다) | 동시 세션이 수십이면 1초에 몇 번이다. 밀어 주려면 알림마다 WebSocket 경로가 하나 더 필요하다 | 알림이 늦다는 보고가 오면 간격을 줄이거나 밀어 주는 길을 만든다 |

| 7 | 사람이 누른 저장(`page.collab.flush` — **저장하고 보기로**)과 제목 바꾸기(`page.collab.title`)는 **필수**다 — 2 줄임에서 빠지는 것은 자동 저장(`page.collab.save`) 하나다(2026-09-29, 병합 전 보안 검토) | 처음 판은 셋을 "자동 저장 셋"으로 불러 함께 뺐고, 사용자는 그 설명으로 "제안대로"를 골랐다. 둘은 자동 저장이 아니라 **누가 저장했고 누가 제목을 바꿨는지** 남기려고 보안 검토가 넣은 기록이다(P7 F3·P9 L2) — 저장의 작성자는 마지막으로 친 사람이라 이것이 없으면 사후 조사가 엉뚱한 사람을 가리킨다. REST 저장(`page.update`)이 필수인 것과도 맞춘다. 사용자의 원칙("필수는 늘" — 만들기·고치기)을 따랐다 | 사용자가 둘도 빼기를 원하면 되돌린다(`AUDIT_MIN_LEVEL` 두 줄) |

남는 것: 낮춘 동안 남지 않은 기록은 되살릴 수 없다. 앱 로그(pino)는 이 단계와 무관하다 — 요청마다 한 줄(`http.request`)이 그대로 남는다.

### J.2 지금 화면의 문제 (수치, 2026-09-29 점검)

- **좁다**: 화면 컴포넌트 21개 가운데 19개가 `.shell`(560px)이다 — 1280~1920px 화면의 29~44%만 쓴다. 관리 표 4개 가운데 3개가 그 폭을 넘쳐 삐져나온다
- **항목이 이어진다**: 폼 24개 가운데 23개에서 label과 input이 둘 다 인라인이다. input·select·label·table·ul·a의 요소 기본 규칙이 하나도 없다(input은 본문 글꼴도 물려받지 않는다). 6번의 LLM 연결 등록이 그 예다
- **칸이 안 보인다**: 입력칸 테두리 #D9DEE6은 흰 바탕 위 1.35:1이다(부품 경계는 3:1이어야 한다 — WCAG 1.4.11). 흐린 글 #6B7380은 지금 바탕 위 4.39:1이다
- **메뉴가 홈 한 줄뿐이다**: 다른 화면에서는 "←" 링크(7가지 문구)로 홈에 돌아와야 한다. `header`·`nav` 랜드마크가 없고 탭 제목은 모두 "workfluence"다
- **체계가 없다**: 정의 없이 쓰는 클래스 6개(linklike 18곳 등), 알림띠로 쓰는 `badge fail` 47곳, 단추의 주·위험 구분과 `:disabled` 모양이 없다, 확인은 브라우저 기본 창 11곳뿐이고 확인 없이 지우는 조치가 7가지다

### J.3 뼈대

#### J.3.1 틀
- **카드 틀(AuthLayout)** — 로그인 전 네 화면과 비밀번호를 바꿔야 하는 동안. 회색 바탕 가운데 카드. 카드 위 h1 "workfluence", 카드 안 h2가 화면 이름이다(로그인 화면만 — 나머지는 카드 제목이 h1)
- **한 틀(AppLayout)** — 로그인한 모든 화면과 잘못된 주소. 위 막대 + 왼쪽 칸 + `main`. `main`은 틀이 한 번만 그리고, 화면은 머리(PageHeader)와 내용만 그린다
- **편집 변형** — 한 틀 안에서 편집 줄(48px, 위 막대 아래에 붙는다)과 회색 바탕을 더한다
- 구현은 React Router의 중첩 경로(`Outlet`)다 — 틀을 빠뜨린 화면이 생길 수 없다
- 본문 바탕은 흰색이다. 회색은 카드 틀과 편집 화면에서만, 종이를 올려놓는 바탕으로 쓴다

#### J.3.2 위 막대 (48px, 전체 폭, 스크롤해도 붙어 있다)
- 첫 초점은 **본문 바로가기**(초점을 받을 때만 보인다)
- 왼쪽: 왼쪽 칸 접기/펴기(`aria-expanded`·`aria-controls`), "workfluence"(홈 링크), 주 메뉴(`nav` "주 메뉴") — 스페이스 · 검색 · LLM 질문 · 휴지통 · 관리. **관리**는 관리 권한이 하나라도 있을 때만 보이고 허용된 첫 관리 화면으로 간다. 지금 구역은 `aria-current` + 굵게 + 아래 2px 막대
- 오른쪽(모두 펼쳐 둔다): 알림(FR-1800 — 지금의 알림 영역을 옮긴다), "{이름}님 ({한글 역할})", 비밀번호 변경(비밀번호가 있는 계정만), 로그아웃
- 전역 검색 칸은 두지 않는다 — 주 메뉴 "검색"으로 간다(사용자 관리·스페이스 관리의 찾기 칸과 이름이 겹치지 않게)
- 1280px에서 한 줄에 들어간다. 이름이 길면 이름만 말줄임하고 전체는 `title`로 보인다

#### J.3.3 왼쪽 칸 — 부품 하나, 문맥 셋
- 폭 256px 한 가지(끌어서 조절하지 않는다), 옅은 회색 바탕, 오른쪽 1px 선. 위 막대 아래에 붙어 칸 안에서만 스크롤한다
- 항목: 높이 32px, 지금 항목은 옅은 파랑 바탕 + 왼쪽 2px 막대 + `aria-current="page"`(막대는 Windows 고대비 모드에서도 남는다)
- **제목(heading)을 두지 않는다** — 묶음 이름은 `nav`·`aside`의 이름과 12px 회색 글이다. 본문 h1과 겹치지 않게
- 문맥
  - **기본**(홈·검색·라벨·알림함·휴지통·비밀번호 변경·관리 다섯·잘못된 주소): "바로가기" — 알림함 · 내 지시문, "관리" — 권한 있는 것만(사용자 관리 · 감사로그 · 스페이스 관리 · 운영 설정 · LLM 연결). 판정은 지금 홈 화면의 `can()` 판정을 옮긴다
  - **스페이스**(스페이스 첫 화면·페이지 보기·편집·이력): 스페이스 이름(글 — 링크도 제목도 아니다)과 "팀 · 키 · Crew N", **스페이스 첫 화면**, **+ 새 페이지**(쓸 수 있을 때만), 페이지 트리(J.5.11)
  - **LLM**(질문·지시문): **새 대화**, **내 지시문**, 대화 목록(고정한 것이 위)
- 접기: 폭이 0이 되고 본문이 넓어진다. 접은 상태는 브라우저가 기억한다(`localStorage`). 1280px보다 좁으면 처음에 접혀 있다. 펴면 본문을 밀어낸다 — 겹쳐 뜨지 않아 초점 가두기가 없다

#### J.3.4 본문 폭 (이 표 한 곳에만 적는다)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--side-w` | 256px (접으면 0) | 왼쪽 칸 |

#### J.3.5 머리·빵부스러기·탭 제목
- **머리(PageHeader)**: 빵부스러기(있을 때만) → 왼쪽 h1(24/32) · 오른쪽 그 화면의 조치(주 단추 하나) → 설명 한 줄. 페이지 보기만 다르다 — 머리 줄에 빵부스러기와 조치를 두고 h1(28/36)은 글 칸 안에 둔다
- **빵부스러기**: `nav` "현재 위치" 안의 `ol`, 마지막 항목은 글(`aria-current`). **스페이스 안에서만** 둔다(스페이스 / 상위 페이지 / 페이지). 구역 이름(스페이스·관리·LLM 질문)은 주 메뉴와 왼쪽 칸이 이미 말한다 — 한 화면에 같은 이름의 링크를 둘 두지 않는다
- 흩어진 "←" 링크 7가지는 없앤다. 시험이 이름으로 누르는 것(**← 보기로**·**← 로그인으로**·**← 뒤로**·**홈으로**·**← 홈**)만 그 자리의 조치로 남긴다
- **탭 제목**: `document.title` = "{h1} - {구역} - workfluence"

#### J.3.6 최소 폭
- 기준 **1280px**(1920×1080에 배율 150%) — E2E 기본 창도 1280이라 가장 좁은 판을 늘 시험한다
- 1024~1279px: 왼쪽 칸이 처음에 접혀 있다. 구획 폼은 칸 열만 줄고 라벨을 위로 올리지 않는다
- 1024px 미만: 가로 스크롤(`body` 최소 폭 1024px). 모바일 배치는 만들지 않는다. 글자 크기는 px로 고정한다 — OS 배율과 브라우저 확대가 그대로 먹는다
- 늘 붙어 있는 높이는 위 막대 48px(편집 화면은 편집 줄을 더해 96px)

### J.5 부품

#### J.5.1 요소 기본값 — 부품을 잊은 화면도 틀리지 않게
- input(글·비밀번호·검색·숫자·날짜·주소)·select·textarea: 높이 36, 1px `--border-strong`, 모서리 4, `font: inherit`, `aria-invalid`면 위험 테두리, `:disabled`면 `--canvas`
- label은 칸 위 한 줄(`display: block`). 체크박스·라디오를 감싼 label만 한 줄 안(상자 + 글)
- a는 `--accent-strong`, 문장·문서 안의 링크에는 밑줄
- ul의 글머리표·들여쓰기는 목록 부품(`.row-list`·`.plain`) 안에서만 없앤다 — 문서 본문의 목록은 그대로
- table은 데이터 표 모양(J.5.5). h1~h3·code·pre·fieldset·legend에도 기본값
- 정의 없이 쓰던 클래스(linklike·secondary·row·button-like·pw-form·read)는 이 체계로 옮기고 지운다. 정의만 있고 안 쓰던 `dl.meta`는 KeyValue로 살리고 `.reason`은 지운다

#### J.5.2 단추 (같은 `button`에 클래스만)

| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 기본 | 흰 바탕, 1px `--border-strong` | 대부분 |
| `.primary` | `--accent` 바탕, 흰 글 | 한 영역에 하나 — 저장·등록·만들기·로그인·편집 |
| `.danger` | 흰 바탕, 글만 위험색(줄마다 빨간 판이 늘어서지 않게) | 삭제·지우기·정지·중지·제거·비밀번호 초기화 |

- `:disabled`는 누를 수 없어 보인다(바탕 `--canvas`, 흐린 글, `cursor: not-allowed`, hover 변화 없음). 누를 수 없는 까닭은 옆에 글로도 보인다

#### J.5.3 Field — 라벨·칸·도움말·오류를 한 덩어리로
- 순서: label(이름만) → 칸 → 도움말(12px 회색, 칸의 `aria-describedby`) → 오류(12px 위험색, 앞에 ×, `role="alert"`, 칸에 `aria-invalid`와 `aria-describedby`)
- **라벨 글은 이름만** — 예: "주소 (OpenAI 호환 API의 /v1까지)" → 라벨 "주소" + 칸 아래 도움말. 필수는 label 밖의 작은 "필수"(`aria-hidden`)와 칸의 `required`
- 칸 폭은 값 길이에 맞춘다: `.w-s` 160(숫자 — 뒤에 단위 글), `.w-m` 320(아이디·이름·모델), `.w-l` 560(주소·제목·설명), `.w-full`(본문·지시·질문)
- 눈 모양 단추(보이기)는 비밀번호 변경 화면에만 둔다 — 로그인·가입·API 키 칸에 두면 이름 찾기("비밀번호"·"API 키")가 그 단추에도 걸린다

#### J.5.4 폼 배치 — 네 가지, 화면마다 하나로 고정 (착수 쟁점 6)

| 모양 | 생김 | 쓰는 곳 |
|---|---|---|
| **구획 폼**(FormSection) | 흰 상자 안에 h2 → 윗선 2px → 줄 목록. 한 줄 = [라벨 열 160px, 옅은 회색 바탕, 700] + [칸 열: 칸 → 도움말·오류, 최대 560]. 줄 사이 1px 선 | LLM 연결 등록 · 운영 설정(묶음 넷, `fieldset`·`legend`) · 스페이스 관리 칸 · 새 페이지 · 지시문 · 템플릿으로 저장 · 페이지 옮기기 · 감사 기록 단계 |
| 위 라벨(FormStack) | 라벨이 칸 위, 항목 사이 16 | 로그인 · 가입 요청 · 아이디·비밀번호 찾기 · 비밀번호 변경 |
| 칸 + 단추 한 줄 | 라벨 · 칸 · 같은 높이의 단추 | 라벨 붙이기 · Crew 추가 · 새 분류 · 팀 스페이스 만들기 · 검색 |
| 거르기 줄(FilterBar) | 옅은 회색 판 한 줄: 칸마다 라벨 + 칸, 거르기, 오른쪽 끝 건수(`aria-live`), `role="search"` | 사용자 관리 · 스페이스 관리 · 감사로그 |

- 단추 줄은 폼 맨 아래 왼쪽에 주 단추가 먼저, 카드 틀에서는 카드 폭 전체, 확인 대화에서는 오른쪽 정렬에 주 단추가 맨 오른쪽
- 라벨을 위에 두라는 업무용 체계들(Carbon·GOV.UK·Primer)과 다른 까닭: 사용자가 고른 것이고(착수 쟁점 6), 우리 라벨은 짧게 두고 설명은 도움말로 빼므로 "긴 라벨에 약하다"는 단점이 작다. 1024px까지 라벨을 위로 올리지 않는다

#### J.5.5 표와 목록
- **데이터 표**: 머리행 옅은 회색·12/16 700·위 2px 선, 줄 최소 40·줄 사이 1px 선·세로선 없음·hover 옅은 회색, 글은 왼쪽·수와 날짜는 오른쪽(`tabular-nums`)·조치는 맨 오른쪽(`.sm`, 이름에 줄 이름 — "{이름} 삭제"). 표 위에 h2. 0건이면 한 줄 빈 상태. **열 순서는 바꾸지 않는다**(시험이 칸 순서로 본다)
- 넘칠 때만 가로 스크롤하는 감싸개(`tabindex="0"`, 역할 없음)
- **`.row-list`**: `ul`/`li`를 그대로 두고 표처럼 그린다 — 버전 이력 · 휴지통 · 알림함 · 검색 결과 · 라벨 결과
- 진짜 표로 바꾸는 것: 홈의 스페이스 목록 · Crew · 첨부 · 분류

#### J.5.6 카드·구획
- 카드: 흰 바탕, 1px `--line`, 모서리 8, 안쪽 20, 카드 사이 24, 머리에 h2와 오른쪽 조치. 카드 안에 카드를 두지 않는다
- 페이지 보기의 라벨·첨부·댓글은 카드 없이 위 1px 선과 h2로 잇는다 — 문서가 주인공이다
- 위험 구역(스페이스 중지·지우기)은 테두리를 위험 선으로

#### J.5.7 알림띠 (Notice)
- 오류·완료·주의·안내 네 가지. 옅은 뜻 색 바탕, 왼쪽 4px 막대, 앞머리의 기호와 낱말("× 오류"·"✓ 완료"·"! 주의"·"i 안내")은 CSS로 붙인다 — 글에 들어가지 않아 알림 문장을 그대로 보는 시험이 통한다
- 역할(`alert`·`status`·`note`)은 지금 쓰는 자리 그대로. **조치한 폼·구획 바로 위**에 둔다
- 떴다 사라지는 알림은 없다. 틀에는 늘 떠 있는 `status`·`alert` 영역을 두지 않는다

#### J.5.8 배지
- 클래스 `.badge`는 그대로, 모양은 모서리 4의 작은 딱지(12/16 700) + 앞 기호. 활성·연결됨 ✓(성공) · 승인 대기 ○(정보) · 잠김·정지·연결 안 됨 ⊘(위험) · 중지됨 ‖(경고) · 종류·역할(회색). 긴 문장은 배지에 담지 않는다

#### J.5.9 빈 상태·불러오기
- 빈 상태: 가운데 한 문장 → 설명 → 할 수 있는 조치 하나. 그림은 없다
- 불러오기: 같은 자리에 회색 한 줄. 로그인 확인 중도 틀 안으로 들인다

#### J.5.10 확인 대화 (ConfirmDialog)
- 브라우저 내장 `<dialog>`와 `showModal()` — 초점 가두기·Esc·맨 위 층을 브라우저가 맡는다(새 의존성 없음)
- 폭 440, 제목(예: "이 첨부를 지울까요?"), 본문에 대상 이름과 되돌릴 수 있는지, 오른쪽에 [그만두기] [확정(`.danger.solid`)]. 처음 초점은 그만두기. 확정 단추 이름은 부른 단추 이름을 품지 않는다
- **묻는 곳(16)**: 지금 브라우저 창으로 묻는 11곳(스페이스 중지·지우기·넘겨받기, 분류 지우기, 사용자 정지, LLM 연결 삭제, 대화·지시문 지우기 등)을 이 모양으로 바꾸고, 첨부 삭제·댓글 삭제·템플릿 지우기·Crew 제거를 더한다. **비밀번호 초기화**도 묻는다(확정 **새로 만든다** — 세션이 끊기고 되돌릴 수 없으며, 초기화 요청 알림은 본인이라는 보증이 아니라 본인 확인을 여기서도 말한다. 병합 전 검토)
- **묻지 않는 곳**: 휴지통에서 되살리는 페이지 삭제, 새 버전을 더하는 버전 복원, 다시 붙이면 되는 라벨 떼기 — 한 일을 알림띠로 알린다

#### J.5.11 페이지 트리
- `ul` "페이지 트리", 단계마다 `li`의 왼쪽 여백 16px(인라인 스타일 그대로 — 시험이 단언한다)
- 줄: [24px 펼치기 단추 또는 같은 폭의 빈 자리] + 제목 링크. 펼치기 단추는 글이 없고 "{제목} 펼치기/접기"라는 이름과 `aria-expanded`만 — 줄 글이 제목으로 시작하고 첫 링크가 제목이다
- 처음에는 모두 펼친다. 지금 페이지는 링크에 `aria-current="page"` + 옅은 파랑 바탕 + 왼쪽 막대, 보이도록 스크롤한다
- 스페이스 틀이 트리 목록(`/api/pages?spaceId=`)을 부르고 스페이스 안의 화면 사이에 들고 있다. 만들기·옮기기·삭제·되살리기 뒤에 다시 받는다

### J.7 접근성 — 지금보다 나아지는 것
- 랜드마크(`header`·주 메뉴·바로가기·관리·현재 위치·`main`), 본문 바로가기, 화면마다 h1 하나, 화면마다 다른 탭 제목
- 입력 테두리 1.35 → 3.7:1, 흐린 글 4.39 → 5.3:1 이상, 모든 요소에 같은 초점 표시, 고대비 모드용 투명 윤곽선
- 색만으로 구분하지 않는다 — 지금 항목(막대 + `aria-current`), 알림띠·배지(기호 + 글), 안 읽음(막대 + 글)
- 도움말·오류는 `aria-describedby`, 오류는 `aria-invalid`(지금은 비밀번호 변경만), 필수는 `required`
- 같이 고치는 결함: 댓글의 label이 칸과 묶이지 않는다, 편집 화면의 label이 div를 가리킨다, 실시간 편집을 끈 편집기가 이름 없는 입력란이다, 첨부 칸에 보이는 라벨이 없다

### J.8 시험

**지키는 규칙** — 화면을 바꿔도 시험이 사람과 같은 길로 찾게.
1. 한 화면에 같은 이름의 링크·단추·제목을 둘 두지 않는다(홈의 메뉴 링크는 위 막대·왼쪽 칸으로 옮기고 본문에서 뺀다, 빵부스러기는 구역 이름을 되풀이하지 않는다)
2. 라벨 글은 지금 이름 그대로. "필수"·단위·도움말은 label 밖
3. 틀(위 막대·왼쪽 칸)에는 `status`·`alert`·`note` 역할, 검색 칸, "이름"이 든 입력란을 두지 않는다
4. 트리: `ul` "페이지 트리", `li` 왼쪽 여백 16(인라인), 첫 링크가 제목, 펼치기 단추는 글 없음, 처음 모두 펼침
5. 그대로 둔다: 표 열 순서, `td .badge`, `section`의 이름("라벨"·"댓글"), `.editor.readonly`, `li.card`
6. 로그인 화면에 눈 모양 단추를 두지 않는다

**새 시험** — `e2e/layout.spec.ts`: 1280·1920px에서 주요 화면 12곳(홈·스페이스·페이지 보기·편집·이력·검색·알림함·휴지통·LLM·사용자 관리·감사로그·LLM 연결)을 열어 가로 스크롤이 없는지, 본문이 900px 이상인지, 편집 화면의 제목·본문 칸 테두리 대비가 3:1 이상인지 본다 — 2·4번을 기계로 판정한다. 틀·왼쪽 칸·확인 대화는 컴포넌트 시험.

**고칠 곳**(추정 E2E 15~25곳, 컴포넌트 시험 6~8개 파일): 홈의 메뉴 링크 단언은 틀의 시험으로 옮긴다, 페이지 보기의 "← {스페이스}"는 빵부스러기로, "← LLM 질문"은 위 막대로, 위 막대의 역할은 한글로, 감사 행위 칸은 `code`만 읽게, 브라우저 확인 창을 기다리던 곳(5곳)은 확인 대화 도우미로, 페이지 제목 링크를 누르는 곳은 "페이지 트리"·"현재 위치" 안으로 좁힌다.

| 6 | 편집 줄에 **넓게 보기**와 짧은 상태 배지(연결 끊김·자동 저장 멈춤)를 둔다 | 편집 줄은 붙어 있고 알림띠는 긴 문서에서 위로 올라가 버린다. 넓게 보기를 바꾸러 보기 화면에 갈 까닭이 없다 |
| 7 | 이력의 버전 목록은 이름("버전 목록")을 가진 목록이다 | 왼쪽 칸 트리에도 "v3" 같은 글이 있다 — 목록 안에서만 찾게 |
| 8 | 확인 대화의 확정 단추 이름은 지운다 · 멈춘다(중지·정지) · 넘겨받는다 · 뺀다(Crew 제거) · 없앤다(대화·지시문) · 새로 만든다(비밀번호 초기화) | 부른 단추의 이름(삭제·지우기·중지·정지)을 품지 않게(J.5.10) — "지우기"를 품는 "지운다"는 대화 **안에서만** 찾으면 겹치지 않지만, 목록 줄의 "{제목} 지우기"와 한 화면에 있는 대화·지시문은 "없앤다"로 둔다 |
| 9 | 운영 설정의 도움말에는 값의 뜻과 바닥(비밀번호 8자·2종, 감사 90일 — `POLICY_FLOOR`)만 보이고 위아래 범위는 보이지 않는다 | 범위 표(`RANGES`)를 공유 계약이 내보내지 않는다 — 서버와 화면은 같은 판정 함수(`validatePolicyPatch`)로 막는다. 범위를 보이려면 공유 계약에 범위를 읽는 함수를 더한다(J.11) |
| 10 | `Field`의 "필수"는 label 밖이다(`.field-head`) | label 안이면 라벨 이름이 "이름필수"가 되어 이름으로 칸을 찾지 못한다(J.5.3의 뜻을 부품이 지키게) |
| 11 | 요소 기본값은 명시도 0(`:where`)이다 | 부품·화면 클래스(칸 폭 `.w-*`, 제목 칸 등)가 요소 기본값에 지지 않게 — 첫 판은 기본값 규칙이 더 세서 카드의 칸이 100%로 늘지 않았다 |
| 12 | 스페이스 관리의 거르기 줄은 찾기 칸에 입력을 멈추면 찾는다(거르기 단추 없음). 감사로그는 **거르기** 단추로 | 예전 동작 그대로 — 스페이스 찾기는 서버가 찾는다(P14 D.4), 감사로그는 칸이 여럿이라 한 번에 보낸다 |
| 13 | 편집·이력의 빵부스러기는 스페이스 / 페이지뿐이다(상위 페이지는 페이지 보기만) | 상위 페이지 사슬은 페이지 보기가 트리 목록으로 만든다. 편집·이력은 왼쪽 칸에서 같은 트리를 보인다 — 필요하면 사슬 만드는 함수를 공유 부품으로 옮긴다 |
| 14 | 페이지 보기는 **주소의 페이지를 읽은 뒤에만** 그 페이지를 그리고(그동안 왼쪽 칸은 제자리, 본문은 불러오는 중), 편집·이력은 페이지마다 화면을 새로 만든다(`key`) | 왼쪽 칸의 트리로 옮기면 화면이 그대로 남아 주소만 바뀐다 — 앞 페이지의 제목과 조치를 보인 채 삭제가 새 페이지로 갔다(병합 전 검토). 보기는 트리의 펼침을 남기려고 본문만 새로 만든다 |
| 15 | 실시간 편집을 끈 편집 화면은 저장하지 않은 편집이 있으면 **창을 닫거나 새로 고칠 때만** 묻는다(`beforeunload`) — 왼쪽 칸·위 막대의 링크로 떠나는 것은 막지 않는다 | 앱 안의 이동을 막는 `useBlocker`는 데이터 라우터(`createBrowserRouter`)에서만 되고 이 앱은 `BrowserRouter`다 — 모든 경로를 다시 짜는 일이라 하지 않았다. 사용자 가이드 5.5절이 먼저 저장하라고 말한다 |
| 16 | 편집기는 창 위의 두 막대(위 막대 + 편집 줄)만큼 띄워 커서를 보이게 한다(`EDIT_SCROLL_MARGIN`, `scroll-padding-top`) — 편집 줄 한 줄(48px)을 전제한다 | 편집기는 기본으로 창 맨 위에서 5px만 띄워 판정해, 막대 뒤에 숨은 커서를 "보인다"고 봤다(병합 전 검토). 편집 줄은 좁은 창이나 같이 보는 사람이 많으면 두 줄로 접힌다 — 그때는 여백이 모자라 커서가 둘째 줄 뒤로 숨을 수 있다(좁은 재점검 N3, 재지 않았다). 보고되면 편집 줄의 높이를 재어 여백에 넣는다 |

### J.11 남는 것 · 하지 않는 것
- 하지 않는다(필요하면 백로그): 페이지마다 폭 저장(마이그레이션), 트리 끌어 옮기기, 즐겨찾기·최근 본 페이지(왼쪽 칸의 기본 문맥이 비어 보이면 여기에 둘 자리다), 왼쪽 칸 폭 끌어 조절, 서식 단추 줄(F-013)
- 운영 설정에 값의 범위가 보이지 않는다(J.12-9)
- 댓글을 지우면 그 댓글에 달린 답도 화면에서 보이지 않는다 — 서버는 원 댓글만 지우지만 목록이 지운 원 댓글의 답을 그리지 않는다(Phase 3부터). 확인 대화가 "달린 답 N개도 보이지 않게 된다"를 말한다
- 페이지 보기·편집·이력은 스페이스를 두 번 부른다(화면과 왼쪽 칸 — 왼쪽 칸은 들고 있던 것을 먼저 보인다). 지금 규모에서 무시할 만하다
- 페이지 보기·편집·이력마다 트리 목록을 부른다 — 페이지가 수천 개인 스페이스에서 무거울 수 있다(재지 않았다). 그렇게 되면 서버가 잘라서 주는 길이 필요하다
- 화면 기본 글자가 16px에서 14px로 준다 — 작게 느껴지면 브라우저 확대(px 고정이라 그대로 먹는다)
- 넓게 보기와 왼쪽 칸 접기는 브라우저에 저장한다 — PC나 브라우저 데이터가 바뀌면 처음 상태다
- 실제 Windows(맑은 고딕 렌더링, 배율 150%, 고대비 모드)와 화면 낭독기(NVDA)는 Linux Chromium 캡처로 대신 본다 — 체험 묶음으로 사용자가 본다
