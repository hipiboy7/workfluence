## 2. 실측

### 2.1 nginx를 거쳐 흘러가는가 (NFR-100·101)

컨테이너 스택(`workfluence-app:cf83d4d-p10`)에서 호스트 → nginx(TLS, 8443) → api → 가짜 vLLM. 가짜 vLLM은 400ms마다 한 조각
(`<think>…</think>` 하나 + 답 다섯)을 보낸다. **TLS 검증을 끄지 않았다** — 개발용 자가서명 인증서를 CA로 믿고 그 이름으로 검증했다.

```
    +   37ms {"type":"thinking","text":"읽는 중"}
    +  427ms {"type":"delta","text":"하나 "}
    +  827ms {"type":"delta","text":"둘 "}
    + 1227ms {"type":"delta","text":"셋 "}
    + 1628ms {"type":"delta","text":"넷 "}
    + 2029ms {"type":"delta","text":"다섯"}
    + 2473ms {"type":"end","status":"done","saved":true,"conversationId":"9dd8b5eb-…","evicted":0,"message":null}
✅ HTTP/1.1로 nginx를 거쳐 흘러간다 — application/x-ndjson; charset=utf-8 · 답 조각 5개가 1602ms에 걸쳐 · 첫 조각 +427ms
✅ HTTP/2로도 흘러간다 — h2 200 · 답 조각 5개가 1601ms에 걸쳐
```

`3d4736e`의 이미지로 다시: HTTP/1.1 답 조각 5개가 1,604ms에 걸쳐(첫 조각 +424ms) · HTTP/2 1,602ms · 떠나면 265ms 안에 끊김 · 로그아웃 멈춤 — 전부 통과.

| 항목 | 값 |
|---|---|
| 조각 사이 | 400ms 간격으로 보낸 것이 400ms 간격으로 온다 — 모았다 보내면 간격이 0에 가깝다 |
| 중계가 더하는 시간 | 약 30ms (가짜 vLLM이 보낸 시각 대비) — NFR-100 "1초 안" |
| HTTP/2 | 브라우저가 쓰는 길(`http2 on`). ALPN `h2`, 같은 간격 |
| 머리말 | `content-type: application/x-ndjson; charset=utf-8` · `cache-control: no-store` |

| 무엇 | 어디서 | 결과 |

| 중지 | 컴포넌트 시험 · E2E | 흐름이 열리기 전에는 눌리지 않는다. 멈출 것이 없다는 답(`stopped:false`)이면 되살아난다. 서버는 저장 중이면 `false` |

### 2.3 끝나지 않는 한 줄 (NFR-102, 보안 검토 1)

보안 검토가 쓴 재현 스크립트(가짜 서버가 줄바꿈 없는 `data:` 한 줄을 30MB 보낸다)를 **고치지 않고** 고친 어댑터에 다시 돌렸다.

| | 걸린 시간 | 힙 최대 증가 | 이벤트 루프 최대 멈춤 | 결과 |
|---|---|---|---|---|
| 고치기 전 (보안 검토의 측정) | 5.6초 | +518MB | 689ms | 끝까지 읽었다 |
| 고친 뒤 | **47ms** | **+1MB** | **8ms** | `LlmError(protocol): LLM 응답의 한 줄이 너무 길다 — …` |

같은 스크립트의 나머지: 넘겨주기는 따르지 않았고(넘겨준 곳에 닿은 수 0), 오류 문장이 키를 되읊으면 `invalid api key: Bearer ***`로
가려졌다. 보이지 않는 글자가 든 키는 어댑터에서는 여전히 "닿지 않는다"이지만, 이제 **등록할 때 DTO가 받지 않는다**(설계서 D.4).

## 4. 실제로 동작시켜 확인한 것

### 4.1 브라우저 — E2E (`e2e/llm.spec.ts`)

| 시험 | 본 것 |
|---|---|
| 시스템 관리자가 LLM을 등록하면 곧바로 연결을 확인한다 — 키는 다시 보이지 않는다 | 등록 → "연결됨", 입력칸의 키가 비고 화면 어디에도 없다, `/v1/models`에 키가 간다 |
| 지시문을 고르고 물으면 답이 흘러나오고, 고정하고 이어 묻는다 | 끝나기 전에 앞 조각이 보인다, 생각 과정은 보이되 저장되지 않는다, 지시문이 `system`으로 먼저 간다, 이어 묻기에 앞 이력이 간다, 감사에 토큰 수는 있고 내용·키는 없다 |
| 중지하면 LLM 요청을 끊고 거기까지 남긴다 | "중지됨", 가짜 vLLM이 끊김을 본다 |
| 페이지를 떠나면 받던 답을 멈춘다 | 2.2 |
| 위키 페이지를 마크다운으로 복사해 질문에 붙인다 | 클립보드에 든 것 그대로 LLM으로 간다 |

전체 28건이 통과했다 — 모든 화면의 API 호출이 지나는 `api()`에 경로 조각 막기를 더했으므로 LLM 밖의 화면도 함께 봤다.

### 4.2 변이 시험 — 떠나면 멈추는가를 시험이 정말 잡는가

| 지운 것 | 잡은 시험 |
|---|---|
| 화면이 떠날 때와 주소로 다른 대화를 열 때 요청을 끊는 두 자리 (`LlmPage.tsx`) | "페이지를 떠나면 받던 답을 멈춘다"·"받는 중에 주소로 다른 대화를 열면" — **둘 다 실패**. 되돌리자 16건 통과 |

## 9. 확인하지 못한 것

- **사내 LLM 실연동** — 가짜 vLLM으로만 봤다. reasoning parser를 켠 서버·끈 서버, 실제 거절 문장(문맥 초과 안내가 붙는지), 키 있음·없음,
  **붐빌 때 첫 조각까지의 시간**, `https` + 사내 CA → 보류 29
- **닫는 태그만 오는 모델**(Qwen3-*-Thinking-2507)의 실제 출력 — 모델 카드가 말하는 모양(`생각…</think>답`)으로만 시험했다
- **긴 답을 그리는 비용** — 50ms마다 모아 그리는 것은 가짜 타이머 시험으로 동작만 봤다. 20만 자 답의 화면 반응은 재지 않았다
- **빈도 제한이 없는 상태**의 실제 모습 → 보류 30
- 만료 정리 타이머(`LlmSweeper`)는 시험 환경에서 돌지 않는다 — 정리 자체(`sweepExpired`)는 통합 시험, 기동 때의 한 번은 컨테이너 로그
  (마이그레이션 뒤라 경고 0)로 봤다
- 관리자가 M을 고정 수 아래로 내린 뒤의 **"보관 n/M" 초과** 상태는 코드 읽기와 상한 시험으로만 봤다
- 경로 조작 막기(`api()`의 점 조각, 화면의 `RequireUuidParam`)는 단위·컴포넌트 시험과 E2E 전체로 봤다 — 페이지에 심은 링크로 관리자
  화면을 여는 공격 자체는 재현하지 않았다
- 클립보드는 Chromium의 `http://127.0.0.1`(보안 문맥)에서 봤다 — 운영은 nginx TLS 뒤라 같은 조건이다. 다른 브라우저는 보지 않았다
