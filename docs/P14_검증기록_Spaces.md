## 3. 돌연변이 — 고친 곳을 옛 코드로 되돌려 봤다

**첫 판** — 서버 여덟(옮기기의 잠금 제거, 받은 자리를 그대로 적기, 형제 다시 매기기 제거, 형제의 고친 시각까지 바꾸기, 찾기 조건 무시, 상태
조건 무시, 와일드카드를 막지 않기, 컨트롤러가 조건을 넘기지 않기)과 화면 열하나 — 처음에 화면 셋이 빠져나가 시험을 더한 뒤 모두 실패했다.

**병합 전 검토를 반영한 뒤** — 모두 새 시험이 실패했다(반영분 점검 뒤의 서버 열셋·화면 셋은 검토서 4절 — 처음에 하나가 빠져나가 시험을 바꿨다).

- 서버 열넷: 만들기·지우기·옮기기가 잠그지 않기, 다시 매기기 문장 빼기, 형제 질의의 스페이스 조건 빼기, 지움 조건 빼기, 다른 스페이스를 400으로
  (옛 코드), 감사에 요청값만(옛 코드), 모든 스페이스를 SQL에서 자르지 않기, 모든 스페이스의 권한 검사 빼기, 만들기의 간격 빼기(옛 +1),
  되살리기의 깊이 판정 빼기, 깊이 판정을 한 칸 어긋나게(`>=`), 잠금을 부모 판정 뒤로.
- 화면 열다섯: `?parent=`를 한 번만 고르지 않기, 트리에 있는지 보지 않기, 위치 값을 트리로 거르지 않기, 옛 읽기를 거르지 않기, 평평한 목록,
  관리 칸을 스페이스 객체에 맞추기, 관리 칸을 id에만 맞추기, 보이지 않아도 분류 읽기, 찾기가 돼도 오류를 남기기, 옛 실패를 거르지 않기, 권한이
  없어도 목록 부르기, 이미 있어도 "만들었다", 줄의 조치가 access를 무시, 옮기기의 고아 부모를 그대로 보내기, 들여쓰기를 보통 공백으로.

- **다시 읽을 때마다 고른 위치가 되돌아갔다** — 엉뚱한 부모 아래에 만들었다(T-065). 시험 셋이 동작 전에도 참이었다(T-066).

반영분만 다시 본 좁은 자체 점검(Opus 5.5) — 15건(중간 4·낮음 11), 오탐 0. **반영이 새로 만든 결함 셋**이 먼저 나왔다: 잠금을 네 길로 넓히며 잠그기
전에 읽은 행을 그대로 썼고(앞사람이 지운 페이지를 옮겼다), 트리를 목록 안의 목록으로 바꾸며 들여쓰기가 단계마다 56px가 됐고, 보류 32에 이미
있는 열을 "마이그레이션이 필요하다"고 적었다. 대문자 식별자로 순환 판정을 넘는 길(P2부터 — T-067)도 찾았다. 14건 반영, 1건은 보류 34.

처리 내역 전부는 [`docs/internal/P14_검토서_Review.md`](internal/P14_검토서_Review.md).

## 9. 확인하지 못한 것

- **동시 옮기기의 겹침 시험은 확률에 기댄다** — 여덟 트랜잭션을 한꺼번에 띄워 잠금이 없으면 자리가 겹치는 것을 봤다(돌연변이에서 실패). 매번
  겹치는 것을 보장하지는 않는다. 잠금의 **순서**는 결정적으로 본다(동시 순환 시험 — 앞의 옮기기를 커밋 전에 붙잡아 둔다)
- 틈이 없어 다시 매길 때의 비용은 그대로다 — 한 문장이어도 본문이 큰 형제 300개면 약 1.2초(시험 DB). 틈은 같은 두 이웃 사이에 열 번쯤 거듭
  끼워 넣어야 없어지고, 실제로 얼마나 자주 없어지는지는 재지 않았다(보류 14에 옮기기를 더할 때)
- 잠금 대기 2초의 409가 실제 사용에서 얼마나 뜨는지 — 부하 측정(보류 14)에 쓰기가 없다
- 칸을 연 뒤 같은 부모 아래가 바뀌면 한 칸 어긋나는 것(설계서 D.5)은 시험하지 않았다 — 오류가 아니라 뜻이 그렇다
- 브라우저 E2E는 chromium 하나다(`e2e/playwright.config.ts`) — Windows에서 같은 34가 도는지는 `exp/windows`가 `main`을 다시 들인 뒤에 본다
